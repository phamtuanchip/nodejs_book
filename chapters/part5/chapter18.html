Chương 18: Serverless và Cloud Functions

"Serverless" không có nghĩa là không có server — có nghĩa là bạn không cần quản lý server. Viết function, deploy, và chỉ trả tiền khi có request. Chương này giới thiệu paradigm hiện đại nhất của cloud computing và khi nào nên dùng nó.

  • Biết cold start là gì và cách giảm thiểu
  • Deploy API lên Vercel Functions trong 5 phút
  • Viết AWS Lambda handler chuẩn

18.1 Serverless là gì?

Mô hình traditional: bạn thuê VPS chạy 24/7 kể cả lúc không có request nào. Bạn phải lo cập nhật OS, scale khi traffic tăng, xử lý khi server chết.

Mô hình serverless: bạn chỉ upload code (một function). Cloud provider tự lo chạy, scale từ 0 đến hàng nghìn instances, và bạn chỉ trả tiền cho số lần function được gọi.

Ưu và nhược điểm

Ưu điểm ✅Nhược điểm ❌
Serverless Không quản lý infra, auto scale, pay-per-use, deploy nhanh Cold start, stateless, time limit (~15 min), vendor lock-in
Traditional Full control, persistent connections (WebSocket), dễ debug local Quản lý server, trả tiền idle, phải tự scale

18.2 Cold Start — Vấn Đề Đặc Trưng

Khi function chưa được gọi gần đây, cloud platform phải boot container mới, load code, khởi tạo connections — trước khi xử lý request. Đây gọi là cold start.

Cách giảm cold start

  • Giảm dependencies: chỉ import những gì cần, tránh heavy packages
  • Keep connections ngoài handler: kết nối DB một lần, tái dùng giữa các invocations
  • Provisioned Concurrency (AWS Lambda): giữ N instances luôn warm, tốn thêm tiền
  • Cloudflare Workers: không có cold start vì dùng V8 isolates thay vì containers
JavaScriptKết nối DB ngoài handler — tái dùng giữa invocations
const mongoose = require('mongoose');

// Kết nối một lần, tái dùng trong mọi invocation
let isConnected = false;

async function connectDB() {
  if (isConnected) return;  // Đã kết nối rồi
  await mongoose.connect(process.env.MONGODB_URI);
  isConnected = true;
}

// Handler
exports.handler = async (event) => {
  await connectDB();  // Chỉ thực sự connect lần đầu
  // ... xử lý request
};

18.3 Vercel Functions — Dễ nhất để bắt đầu

Vercel là nền tảng deploy phổ biến nhất cho Next.js và static sites, nhưng cũng có Serverless Functions rất dễ dùng — không cần cấu hình gì.

Cách hoạt động

Mọi file trong thư mục api/ tự động trở thành một serverless endpoint.

JavaScriptapi/hello.js → GET /api/hello
// Vercel Function đơn giản nhất
export default function handler(req, res) {
  const { name = 'World' } = req.query;
  res.status(200).json({
    message: `Xin chào ${name}!`,
    timestamp: new Date().toISOString(),
    method: req.method,
  });
}
JavaScriptapi/users/[id].js → GET /api/users/123 (dynamic route)
import mongoose from 'mongoose';

let isConnected = false;

async function dbConnect() {
  if (isConnected) return;
  await mongoose.connect(process.env.MONGODB_URI);
  isConnected = true;
}

const UserSchema = new mongoose.Schema({ name: String, email: String });
const User = mongoose.models.User || mongoose.model('User', UserSchema);

export default async function handler(req, res) {
  await dbConnect();

  const { id } = req.query;

  if (req.method === 'GET') {
    const user = await User.findById(id);
    if (!user) return res.status(404).json({ error: 'Không tìm thấy user' });
    return res.json({ data: user });
  }

  if (req.method === 'PUT') {
    const user = await User.findByIdAndUpdate(id, req.body, { new: true });
    return res.json({ data: user });
  }

  if (req.method === 'DELETE') {
    await User.findByIdAndDelete(id);
    return res.status(204).end();
  }

  res.status(405).json({ error: 'Method not allowed' });
}

18.4 AWS Lambda

AWS Lambda là serverless platform lớn nhất thế giới — mạnh mẽ hơn nhưng cũng phức tạp hơn Vercel. Phù hợp cho các ứng dụng enterprise hoặc khi cần tích hợp sâu với các AWS services. 

JavaScripthandler.js — Lambda function chuẩn
// Lambda nhận event từ API Gateway
exports.handler = async (event, context) => {
  // context.callbackWaitsForEmptyEventLoop = false; // Cho phép reuse DB connection

  const { httpMethod, path, body, queryStringParameters, pathParameters } = event;

  try {
    // Router đơn giản
    if (httpMethod === 'GET' && path === '/users') {
      const users = [{ id: 1, name: 'Alice' }]; // thay bằng DB query
      return response(200, { data: users });
    }

    if (httpMethod === 'GET' && path.startsWith('/users/')) {
      const { id } = pathParameters;
      return response(200, { data: { id, name: 'Alice' } });
    }

    if (httpMethod === 'POST' && path === '/users') {
      const data = JSON.parse(body || '{}');
      // validate + save to DB
      return response(201, { data: { id: Date.now(), ...data } });
    }

    return response(404, { error: 'Route không tồn tại' });

  } catch (err) {
    console.error('Lambda error:', err);
    return response(500, { error: 'Lỗi server' });
  }
};

function response(statusCode, body) {
  return {
    statusCode,
    headers: {
      'Content-Type': 'application/json',
      'Access-Control-Allow-Origin': '*',
    },
    body: JSON.stringify(body),
  };
}
YAMLserverless.yml — Dùng Serverless Framework
service: my-api

provider:

18.5 Cloudflare Workers — Edge Computing

Cloudflare Workers chạy code ở edge — tức là ở hơn 300 datacenter gần người dùng nhất trên toàn cầu. Response time < 50ms vì code chạy ngay gần user, không phải round trip về US hay Singapore.

📌 Workers khác Lambda ở chỗ nào?
Workers dùng V8 Isolates thay vì Docker containers. Mỗi isolate boot trong microseconds thay vì hàng trăm ms → không có cold start. Nhưng Workers có giới hạn: không có filesystem, hạn chế Node.js APIs, không có native modules. 
JavaScriptsrc/worker.js
// Cloudflare Workers dùng Web Standard APIs
export default {
  async fetch(request, env, ctx) {
    const url = new URL(request.url);

    // Router
    if (url.pathname === '/api/hello') {
      return Response.json({
        message: 'Xin chào từ Edge!',
        location: request.cf?.city || 'Unknown',
        country: request.cf?.country || 'Unknown',
      });
    }

    if (url.pathname === '/api/cache-demo') {
      const cacheKey = new Request(url.toString());
      const cache = caches.default;

      // Check cache
      let response = await cache.match(cacheKey);
      if (response) {
        return new Response(response.body, {
          headers: { ...response.headers, 'X-Cache': 'HIT' }
        });
      }

      // Cache miss: fetch data
      const data = { timestamp: Date.now(), data: 'expensive computation' };
      response = Response.json(data, {
        headers: { 'Cache-Control': 'public, max-age=60' }
      });

      ctx.waitUntil(cache.put(cacheKey, response.clone()));
      return new Response(response.body, {
        headers: { ...response.headers, 'X-Cache': 'MISS' }
      });
    }

    // KV Storage (Cloudflare's global key-value store)
    if (url.pathname.startsWith('/api/kv/')) {
      const key = url.pathname.slice(8);
      if (request.method === 'GET') {
        const value = await env.MY_KV.get(key);
        return value
          ? Response.json({ key, value })
          : new Response('Not found', { status: 404 });
      }
      if (request.method === 'PUT') {
        const body = await request.text();
        await env.MY_KV.put(key, body, { expirationTtl: 3600 });
        return Response.json({ ok: true });
      }
    }

    return new Response('Not Found', { status: 404 });
  }
};

18.6 Khi nào dùng Serverless vs Server truyền thống?

Tiêu chí Serverless ✅ Traditional Server ✅
Traffic pattern Spiky, không đều Steady, cao liên tục
Request type Short-lived (< 15 phút) Long-running, WebSocket
Team Startup, MVP, ít DevOps Có DevOps, cần full control
Cost (low traffic) Rất rẻ (có thể $0) Tốn tiền ngay cả lúc idle
Cost (high traffic) Có thể đắt hơn VPS Dự đoán được, thường rẻ hơn
Latency Cold start có thể chậm Consistent, không có cold start
Ví dụ phù hợp API, webhooks, cron jobs, image processing Chat app, game server, admin dashboard
💡 Hybrid Architecture
Không cần chọn một. Nhiều app dùng cả hai: Express trên VPS cho core API, Cloudflare Workers cho edge caching, Lambda cho background jobs và webhooks.
📚 Tóm tắt chương 18
  • Serverless: code chạy theo yêu cầu, auto scale, pay-per-use — không phải không có server mà là không quản lý server
  • Cold start: delay lần đầu invoke khi container chưa warm — giảm bằng cách giữ connections ngoài handler và giảm dependencies
  • Vercel Functions: file trong api/ tự thành endpoint — dễ nhất để bắt đầu
  • AWS Lambda: handler function nhận event từ API Gateway, trả về object có statusCode và body
  • Cloudflare Workers: V8 isolates, không có cold start, chạy ở edge (300+ locations), dùng Web Standard APIs
  • Chọn serverless khi traffic spiky, request ngắn, team nhỏ. Chọn VPS khi traffic đều, cần WebSocket, hoặc high traffic
