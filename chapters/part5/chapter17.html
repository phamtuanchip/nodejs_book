Chương 17: Deploy và DevOps Cơ Bản

Code chạy trên máy local chưa phải sản phẩm. Chương này đưa ứng dụng lên internet — từ cấu hình môi trường, Docker, Nginx, SSL đến CI/CD pipeline tự động deploy mỗi khi bạn push code.

🎯 Sau chương này bạn sẽ
  • Quản lý environment variables đúng cách cho production
  • Dùng PM2 giữ cho Node process luôn chạy
  • Đóng gói ứng dụng bằng Docker và docker-compose
  • Deploy lên VPS với Nginx làm reverse proxy
  • Cài SSL miễn phí với Let's Encrypt
  • Tự động deploy với GitHub Actions CI/CD

17.1 Environment Variables — Cấu Hình Production

Hardcode URL database, API key, hay secret vào source code là lỗi phổ biến nhất của developer mới. Nếu commit lên GitHub, bất kỳ ai cũng đọc được. Environment variables giải quyết vấn đề này. 

Shell.env
# .env — KHÔNG commit file này!
NODE_ENV=development
PORT=3000
MONGODB_URI=mongodb+srv://user:pass@cluster.mongodb.net/mydb
JWT_SECRET=super-secret-key-ít-nhất-32-ký-tự
REDIS_URL=redis://localhost:6379
CORS_ORIGIN=http://localhost:5173
Shell.env.example
# .env.example — COMMIT file này, làm template cho team
NODE_ENV=development
PORT=3000
MONGODB_URI=mongodb+srv://USER:PASS@cluster.mongodb.net/DBNAME
JWT_SECRET=your-secret-here-min-32-chars
REDIS_URL=redis://localhost:6379
CORS_ORIGIN=http://localhost:5173
JavaScriptsrc/config/env.js
require('dotenv').config();

const requiredVars = [
  'MONGODB_URI',
  'JWT_SECRET',
];

// Fail fast: kiểm tra ngay khi khởi động
for (const key of requiredVars) {
  if (!process.env[key]) {
    console.error(`❌ Missing required env var: ${key}`);
    process.exit(1);
  }
}

module.exports = {
  nodeEnv:     process.env.NODE_ENV || 'development',
  port:        parseInt(process.env.PORT) || 3000,
  mongoUri:    process.env.MONGODB_URI,
  jwtSecret:   process.env.JWT_SECRET,
  redisUrl:    process.env.REDIS_URL || 'redis://localhost:6379',
  corsOrigin:  process.env.CORS_ORIGIN || '*',
  isDev:       process.env.NODE_ENV !== 'production',
};

17.2 PM2 — Process Manager

Khi chạy node app.js thẳng, nếu server crash thì… chết. PM2 tự động restart khi crash, quản lý logs, và tận dụng nhiều CPU core qua cluster mode. 

ShellTerminal
# Cài global
npm install -g pm2

# Chạy app
pm2 start src/index.js --name my-api

# Cluster mode — dùng hết CPU cores
pm2 start src/index.js --name my-api -i max

# Xem status
pm2 status
pm2 monit        # Dashboard real-time

# Logs
pm2 logs my-api
pm2 logs my-api --lines 100

# Restart / reload (zero-downtime)
pm2 restart my-api
pm2 reload my-api    # graceful — không drop connections

# Tự start lại khi server reboot
pm2 startup          # follow hướng dẫn in ra
pm2 save             # lưu danh sách process hiện tại
JavaScriptecosystem.config.js
module.exports = {
  apps: [{
    name: 'my-api',
    script: 'src/index.js',
    instances: 'max',        // dùng tất cả CPU cores
    exec_mode: 'cluster',
    watch: false,            // tắt trong production
    max_memory_restart: '500M',
    env: {
      NODE_ENV: 'development',
      PORT: 3000,
    },
    env_production: {
      NODE_ENV: 'production',
      PORT: 3000,
    },
    log_date_format: 'YYYY-MM-DD HH:mm:ss',
    error_file: 'logs/error.log',
    out_file: 'logs/out.log',
    merge_logs: true,
  }],
};

// Chạy với: pm2 start ecosystem.config.js --env production

17.3 Docker — Đóng Gói Ứng Dụng

"Chạy được trên máy tôi mà" — câu nói kinh điển của developer. Docker giải quyết bằng cách đóng gói cả code, runtime, và dependencies vào một container chạy được ở mọi nơi giống hệt nhau. 

DockerfileDockerfile
# ---- Build stage ----
FROM node:20-alpine AS builder
WORKDIR /app
# Copy package files trước để cache layer khi code thay đổi
COPY package*.json ./
RUN npm ci --only=production

# ---- Production stage ----
FROM node:20-alpine
WORKDIR /app
# Copy chỉ node_modules và source, không copy devDependencies
COPY --from=builder /app/node_modules ./node_modules
COPY . .
# Không chạy với root user
USER node
EXPOSE 3000
CMD ["node", "src/index.js"]

    ports:
      - "6379:6379"

      - redis_data:/data
    restart: unless-stopped

17.4 Deploy lên VPS

Hướng dẫn từng bước với DigitalOcean Droplet (Ubuntu 22.04, ~$6/tháng) — tương tự mọi VPS khác.

ShellTrên server — Lần đầu setup
# 1. SSH vào server
ssh root@YOUR_SERVER_IP

# 2. Update hệ thống
apt update && apt upgrade -y

# 3. Cài NodeJS với nvm
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
source ~/.bashrc
nvm install --lts
nvm use --lts

# 4. Cài PM2, Git
npm install -g pm2
apt install -y git

# 5. Clone project
git clone https://github.com/your-user/your-repo.git /app
cd /app

# 6. Cài dependencies
npm install --production

# 7. Tạo file .env
cp .env.example .env
nano .env          # điền các giá trị thực

# 8. Start với PM2
pm2 start ecosystem.config.js --env production
pm2 save
pm2 startup        # copy paste lệnh in ra

# 9. Firewall
ufw allow 22        # SSH
ufw allow 80        # HTTP
ufw allow 443       # HTTPS
ufw enable
ShellDeploy code mới sau này
cd /app
git pull origin main
npm install --production
pm2 reload my-api    # zero-downtime restart

17.5 Nginx — Reverse Proxy

Không nên expose NodeJS thẳng ra internet. Nginx đứng trước làm reverse proxy: xử lý SSL, static files, load balancing, và bảo vệ server. 

ShellCài và cấu hình Nginx
# Cài Nginx
apt install -y nginx

# Tạo config site
nano /etc/nginx/sites-available/my-api
Nginx/etc/nginx/sites-available/my-api
server {
    listen 80;
    server_name yourdomain.com www.yourdomain.com;

    # Giới hạn body size (upload)
    client_max_body_size 10M;

    location / {
        proxy_pass http://localhost:3000;
        proxy_http_version 1.1;

        # WebSocket support
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';

        # Forward thông tin thực của client
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # Timeout
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }

    # Serve static files trực tiếp, không qua NodeJS
    location /uploads {
        alias /app/uploads;
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}
ShellKích hoạt site
# Tạo symlink để enable site
ln -s /etc/nginx/sites-available/my-api /etc/nginx/sites-enabled/

# Test config hợp lệ
nginx -t

# Reload Nginx
systemctl reload nginx

17.6 SSL với Let's Encrypt

HTTPS là bắt buộc cho mọi site production. Certbot tự động cài SSL miễn phí từ Let's Encrypt.

ShellCài SSL
# Cài Certbot
snap install --classic certbot

# Cài SSL và tự cấu hình Nginx
certbot --nginx -d yourdomain.com -d www.yourdomain.com

# Certbot sẽ:
# 1. Xác thực domain ownership
# 2. Lấy certificate từ Let's Encrypt
# 3. Cấu hình Nginx tự động (thêm HTTPS, redirect HTTP → HTTPS)
# 4. Cài cron job tự renew (cert có hiệu lực 90 ngày)

# Test tự động renew
certbot renew --dry-run
💡 Domain phải trỏ về server trước
Certbot cần verify bạn sở hữu domain. Trỏ DNS A record của domain về IP của VPS ít nhất 5-10 phút trước khi chạy certbot.

17.7 GitHub Actions — CI/CD Pipeline

Thay vì SSH vào server bằng tay mỗi lần deploy, GitHub Actions tự động chạy test và deploy mỗi khi push code lên branch main. 

YAML.github/workflows/deploy.yml
name: CI/CD Pipeline

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  # Job 1: Chạy tests
  test:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Run linter
        run: npm run lint

      - name: Run tests
        run: npm test
        env:
          NODE_ENV: test
          MONGODB_URI: ${{ secrets.TEST_MONGODB_URI }}
          JWT_SECRET: test-secret

  # Job 2: Deploy (chỉ chạy khi push main, sau khi test pass)
  deploy:
    needs: test          # chờ test pass mới chạy
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'

    steps:
      - name: Deploy via SSH
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.SERVER_IP }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SSH_PRIVATE_KEY }}
          script: |
            cd /app
            git pull origin main
            npm install --production
            pm2 reload ecosystem.config.js --env production
            echo "✅ Deploy thành công!"

Cấu hình GitHub Secrets

Vào GitHub repo → Settings → Secrets and variables → Actions → New repository secret:

  • SERVER_IP — IP address của VPS
  • SERVER_USER — username SSH (thường là root hoặc ubuntu)
  • SSH_PRIVATE_KEY — nội dung file ~/.ssh/id_rsa trên máy local
  • TEST_MONGODB_URI — MongoDB URI cho test environment
⚠️ Bảo mật SSH key
Chạy ssh-keygen -t ed25519 -C "github-actions" tạo key riêng cho CI/CD. Copy public key vào ~/.ssh/authorized_keys trên server. Copy private key vào GitHub Secret. KHÔNG dùng key của bản thân.

17.2 docker-compose Full Stack

Viết docker-compose.yml chạy 3 services: API (NodeJS), MongoDB, Redis. API phải kết nối MongoDB và Redis qua service names (không phải localhost). Thêm healthcheck cho MongoDB. Thêm volume để data không mất khi restart. Chạy docker-compose up -d và test toàn bộ flow login → cache → logout.

17.3 CI/CD Pipeline hoàn chỉnh

Setup GitHub Actions CI/CD thực tế: (1) Job test chạy Jest + coverage report, fail nếu coverage < 70%. (2) Job build Docker image và push lên Docker Hub. (3) Job deploy SSH vào server, pull image mới, restart container. Dùng Oracle Cloud Free Tier hoặc Fly.io làm server miễn phí. Bonus: thêm Slack notification khi deploy thành công/thất bại.
