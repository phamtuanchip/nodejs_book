Chương 2: Stateful vs Stateless — Cookie, Session & Browser Storage

HTTP vốn là giao thức "hay quên" — mỗi request là một cuộc trò chuyện mới hoàn toàn. Chương này giải thích tại sao cần lưu "trạng thái" và các cách khác nhau để làm điều đó, từ cookie đến localStorage đến session server.

🎯 Sau chương này bạn sẽ hiểu được
  • HTTP là stateless nghĩa là gì và tại sao đây là vấn đề
  • Cookie là gì, hoạt động thế nào, và các tùy chọn bảo mật
  • Sự khác biệt giữa localStorage, sessionStorage và IndexedDB
  • Server Session và JWT Token khác nhau ở đâu
  • Khi nào dùng cái nào trong thực tế

2.1 HTTP là Stateless — Vấn đề gì?

Ở chương trước, bạn đã biết HTTP là giao thức giao tiếp giữa client và server. Điều quan trọng cần biết: HTTP là stateless — không có trạng thái.

Điều này có nghĩa là: mỗi HTTP request là độc lập hoàn toàn. Server không nhớ bạn từ request trước. Hãy xem ví dụ:

Đây là bản chất của HTTP — mỗi request là một tờ giấy trắng. Server không có "ký ức". Vậy làm sao các website biết bạn đã đăng nhập? Đó là lúc chúng ta cần cơ chế lưu state.

State là gì?

State là thông tin cần được ghi nhớ giữa các request. Ví dụ:

  • Bạn đã đăng nhập chưa? (authentication state)
  • Giỏ hàng của bạn có gì? (shopping cart state)
  • Ngôn ngữ bạn đang dùng là tiếng Việt hay tiếng Anh? (preference state)
  • Bạn đang ở trang nào trong wizard nhiều bước? (form state)

2.2 Cookie — Cách Web "Nhớ" Bạn

Cookie là gì?

Cookie là một mẩu dữ liệu nhỏ mà server gửi cho browser, và browser sẽ tự động gửi lại trong mọi request tiếp theo đến cùng domain đó.

Tạo cookie với JavaScript (phía client)

        

          JavaScript
          cookie-basic.js
          
        

        // Đặt cookie (có hiệu lực 7 ngày)
document.cookie = "username=alice; max-age=604800; path=/";

// Đặt nhiều cookie (mỗi lần chỉ set được 1)
document.cookie = "theme=dark; max-age=2592000; path=/";
document.cookie = "lang=vi; max-age=2592000; path=/";

// Đọc tất cả cookie (trả về chuỗi, không tiện lắm)
console.log(document.cookie);
// "username=alice; theme=dark; lang=vi"

// Hàm tiện ích để đọc 1 cookie theo tên
function getCookie(name) {
  const value = `; ${document.cookie}`;
  const parts = value.split(`; ${name}=`);
  if (parts.length === 2) return parts.pop().split(';').shift();
  return null;
}

console.log(getCookie('username')); // "alice"
console.log(getCookie('theme'));    // "dark"

// Xóa cookie bằng cách đặt max-age = 0
document.cookie = "username=; max-age=0; path=/";

Các thuộc tính quan trọng của Cookie

Thuộc tính Ý nghĩa Khi nào dùng
max-age Thời gian sống (giây). max-age=0 xóa cookie Mọi cookie cần hết hạn
expires Ngày hết hạn cụ thể Thay thế cho max-age
path Cookie chỉ gửi khi URL bắt đầu bằng path này path=/ = toàn site
domain Domain nào nhận cookie Subdomain sharing
HttpOnly JS không đọc được — chỉ browser gửi tự động Session token — bảo vệ XSS
Secure Chỉ gửi qua HTTPS Mọi cookie nhạy cảm
SameSite Kiểm soát khi nào cookie được gửi cross-site Chống CSRF attack
⚠️ Bảo mật Cookie
Cookie session token phải luôn có HttpOnly và Secure. HttpOnly ngăn JavaScript đọc cookie (bảo vệ khỏi XSS attack). Secure đảm bảo cookie chỉ truyền qua HTTPS (tránh bị nghe lén).

Giới hạn của Cookie

  • Tối đa ~4KB mỗi cookie
  • Tối đa ~50 cookie mỗi domain
  • Tự động gửi trong mọi request — tăng bandwidth
  • Người dùng có thể tắt cookie

2.3 localStorage và sessionStorage

Không phải lúc nào cũng cần gửi dữ liệu lên server. Đôi khi chỉ cần lưu trong browser. JavaScript có hai cơ chế lưu trữ phía client:

localStorage

Lưu vĩnh viễn trong browser — không mất khi đóng tab, thậm chí đóng browser.

        

          JavaScript
          localstorage-demo.js
          
        

        // Lưu dữ liệu đơn giản
localStorage.setItem('theme', 'dark');
localStorage.setItem('lang', 'vi');

// Lưu object (phải JSON.stringify)
const user = { name: 'Alice', age: 25, role: 'admin' };
localStorage.setItem('user', JSON.stringify(user));

// Đọc dữ liệu
const theme = localStorage.getItem('theme');    // "dark"
const lang = localStorage.getItem('lang');      // "vi"
const userStr = localStorage.getItem('user');   // chuỗi JSON
const userObj = JSON.parse(userStr);            // { name: "Alice", ... }

// Xóa
localStorage.removeItem('lang');

// Xóa hết
localStorage.clear();

// Kiểm tra số lượng
console.log(localStorage.length); // số keys

// Duyệt qua tất cả
for (let i = 0; i < localStorage.length; i++) {
  const key = localStorage.key(i);
  const value = localStorage.getItem(key);
  console.log(`${key}: ${value}`);
}

sessionStorage

Tương tự localStorage nhưng xóa ngay khi đóng tab.

        

          JavaScript
          sessionstorage-demo.js
          
        

        // API y hệt localStorage, chỉ khác vòng đời
sessionStorage.setItem('checkout_step', '2');
sessionStorage.setItem('cart_total', '1500000');

// Dùng cho dữ liệu tạm thời trong 1 phiên làm việc
// Ví dụ: lưu bước hiện tại trong form đặt hàng nhiều bước
const currentStep = sessionStorage.getItem('checkout_step');
console.log('Đang ở bước:', currentStep); // "2"

// Khi user đóng tab → sessionStorage tự xóa
// Tab mới mở lại → trống rỗng

So sánh Cookie vs localStorage vs sessionStorage

Cookie localStorage sessionStorage
Dung lượng ~4KB ~5-10MB ~5-10MB
Thời gian sống Theo max-age/expires Vĩnh viễn Đến khi đóng tab
Tự gửi lên server ✅ Có ❌ Không ❌ Không
JS có đọc được Chỉ khi không có HttpOnly ✅ Luôn có ✅ Luôn có
Chia sẻ giữa tab ✅ Có ✅ Có ❌ Mỗi tab riêng
Dùng cho Auth token, session Preferences, cache Form state, wizard

2.4 Server Session — "Nhớ" Phía Server

Cookie chỉ lưu dữ liệu ở client. Nhưng để bảo mật, dữ liệu nhạy cảm (như thông tin user đang đăng nhập) nên lưu ở server. Đây là cơ chế Server Session:

📌 Tại sao không lưu luôn data trong cookie?
Kỹ thuật này gọi là session reference — cookie chỉ chứa một ID ngẫu nhiên, dữ liệu thực sự ở server. Điều này:
  • Bảo mật hơn — user không thể giả mạo dữ liệu
  • Có thể lưu lượng lớn dữ liệu (không bị giới hạn 4KB)
  • Có thể vô hiệu hóa session từ server (đăng xuất bắt buộc)

2.5 JWT Token — Session Không Cần Server Lưu

Server Session có một nhược điểm: cần lưu trữ session ở đâu đó (RAM hoặc database). Với hàng triệu user, điều này tốn tài nguyên và phức tạp khi scale.

JWT (JSON Web Token) giải quyết bằng cách mã hóa dữ liệu ngay trong token: 

        

          JavaScript
          jwt-concept.js (chạy trong NodeJS)
          
        

        // Cài đặt: npm install jsonwebtoken
const jwt = require('jsonwebtoken');

const SECRET_KEY = 'khoa-bi-mat-cua-ban-phai-dai-va-kho-doan';

// Tạo token khi đăng nhập thành công
function createToken(userId, role) {
  return jwt.sign(
    { userId, role },           // payload (dữ liệu muốn lưu)
    SECRET_KEY,                  // khóa bí mật để ký
    { expiresIn: '7d' }         // hết hạn sau 7 ngày
  );
}

// Xác thực token từ request
function verifyToken(token) {
  try {
    const decoded = jwt.verify(token, SECRET_KEY);
    return { ok: true, data: decoded };
  } catch (err) {
    return { ok: false, error: err.message };
  }
}

// Sử dụng
const token = createToken(42, 'admin');
console.log('Token:', token);

const result = verifyToken(token);
console.log('Verified:', result);
// { ok: true, data: { userId: 42, role: 'admin', iat: ..., exp: ... } }

// Giả mạo token sẽ fail
const fakeToken = token.slice(0, -5) + 'XXXXX';
console.log('Fake token:', verifyToken(fakeToken));
// { ok: false, error: 'invalid signature' }

So sánh Server Session vs JWT

Server Session JWT Token
Lưu dữ liệu ở đâu Server (RAM/DB) Client (cookie/localStorage)
Vô hiệu hóa tức thì ✅ Dễ (xóa khỏi store) ❌ Khó (phải dùng blacklist)
Scale (nhiều server) Cần shared store (Redis) ✅ Dễ (verify bằng key)
Lưu được dữ liệu lớn ✅ Có ❌ Token sẽ rất to
Phù hợp cho Web app truyền thống API, microservices, mobile app

2.6 Code mẫu — Shopping Cart với localStorage

        

          JavaScript
          shopping-cart.js
          
        

        // ============ Shopping Cart với localStorage ============

const CART_KEY = 'my_cart';

// Đọc giỏ hàng từ localStorage
function getCart() {
  const data = localStorage.getItem(CART_KEY);
  return data ? JSON.parse(data) : [];
}

// Lưu giỏ hàng vào localStorage
function saveCart(cart) {
  localStorage.setItem(CART_KEY, JSON.stringify(cart));
}

// Thêm sản phẩm vào giỏ
function addToCart(product) {
  const cart = getCart();
  const existing = cart.find(item => item.id === product.id);

  if (existing) {
    existing.quantity += 1;   // Tăng số lượng nếu đã có
  } else {
    cart.push({ ...product, quantity: 1 });  // Thêm mới
  }

  saveCart(cart);
  return cart;
}

// Xóa sản phẩm
function removeFromCart(productId) {
  const cart = getCart().filter(item => item.id !== productId);
  saveCart(cart);
  return cart;
}

// Tính tổng tiền
function getTotal() {
  return getCart().reduce((sum, item) => sum + item.price * item.quantity, 0);
}

// Xóa toàn bộ giỏ hàng
function clearCart() {
  localStorage.removeItem(CART_KEY);
}

// ============ Sử dụng ============

addToCart({ id: 1, name: 'iPhone 15', price: 25000000 });
addToCart({ id: 2, name: 'AirPods', price: 5000000 });
addToCart({ id: 1, name: 'iPhone 15', price: 25000000 }); // +1 qty

console.log('Giỏ hàng:', getCart());
// [{ id: 1, name: 'iPhone 15', price: 25000000, quantity: 2 },
//  { id: 2, name: 'AirPods', price: 5000000, quantity: 1 }]

console.log('Tổng tiền:', getTotal().toLocaleString('vi-VN'), 'VND');
// 55.000.000 VND

removeFromCart(2);
console.log('Sau khi xóa AirPods:', getCart().length, 'sản phẩm');

2.7 Stateful vs Stateless Application

Nhìn lại toàn cảnh, có hai kiểu thiết kế ứng dụng web:

Stateful Stateless
Server nhớ gì? Nhớ thông tin user giữa requests (session) Không nhớ gì — mỗi request tự đầy đủ
Ví dụ Web app dùng Server Session REST API dùng JWT
Scale Phức tạp hơn (sticky sessions) Dễ dàng (bất kỳ server nào cũng xử lý được)
Phù hợp App nội bộ, ít traffic Public API, microservices, high traffic
💡 Xu hướng hiện đại
Hầu hết API hiện đại (đặc biệt khi kết hợp với mobile app hoặc SPA) đều chọn stateless với JWT vì dễ scale và không cần shared session store. Tuy nhiên Server Session vẫn là lựa chọn tốt cho web app truyền thống.
📚 Tóm tắt chương 2
  • HTTP stateless: mỗi request độc lập, server không tự nhớ bạn
  • Cookie: browser tự gửi trong mọi request, giới hạn 4KB, dùng HttpOnly+Secure cho token
  • localStorage: lưu vĩnh viễn, ~5-10MB, chỉ JS đọc được, không tự gửi lên server
  • sessionStorage: như localStorage nhưng xóa khi đóng tab
  • Server Session: cookie chứa ID, server lưu dữ liệu thực — bảo mật, dễ vô hiệu hóa
  • JWT: dữ liệu mã hóa trong token, server không cần lưu — dễ scale

Viết code JavaScript (chạy trong Console) để lưu các preferences vào localStorage: theme (dark/light), fontSize (small/medium/large), language (vi/en). Sau đó viết hàm loadPreferences() đọc về và log ra. Thử đóng tab và mở lại — data có còn không?

Khó

2.4 Dark Mode Persistent

Tạo một trang HTML với button toggle Dark/Light mode. Khi click, trang đổi theme và lưu vào localStorage. Khi mở lại trang (reload), trang phải tự apply đúng theme đã lưu mà không bị flash trắng trước khi JS chạy. Hint: Script đọc localStorage phải chạy ngay trong <head>, trước khi HTML render.
