Chương 1: Internet và Web Hoạt Động Như Thế Nào?

Trước khi viết một dòng NodeJS nào, bạn cần hiểu sân chơi của mình. Chương này giải thích cách dữ liệu di chuyển từ trình duyệt của bạn đến một server ở góc khuất nào đó trên thế giới — và quay trở lại.

🎯 Sau chương này bạn sẽ hiểu được
  • Internet là gì, và Web khác Internet ở chỗ nào
  • Client và Server là ai, nói chuyện với nhau như thế nào
  • HTTP request và response trông như thế nào bên trong
  • URL, IP Address, Domain, DNS hoạt động ra sao
  • Frontend và Backend khác nhau ở đâu

1.1 Internet là gì?

Hãy tưởng tượng Internet như một mạng lưới đường cao tốc khổng lồ nối các máy tính lại với nhau. Khi bạn xem YouTube, máy tính của bạn gửi một "gói dữ liệu" đi qua nhiều trạm trung chuyển, qua cáp quang dưới đáy biển, để đến máy chủ của Google ở đâu đó ở Mỹ — và video quay trở lại chỉ trong vài trăm mili-giây.

Internet là hạ tầng vật lý và giao thức (quy ước) để các máy tính giao tiếp với nhau toàn cầu. Web (World Wide Web) chỉ là một trong những dịch vụ chạy trên Internet — cùng với Email, FTP, SSH, v.v.

1.2 Client và Server

Trong thế giới web, mọi cuộc trò chuyện đều có hai vai:

  • Client — người hỏi. Thường là trình duyệt web (Chrome, Firefox), app di động, hoặc bất kỳ chương trình nào yêu cầu dữ liệu.
  • Server — người trả lời. Là máy tính (thường rất mạnh) chạy 24/7, lắng nghe và phản hồi các yêu cầu.
📌 Quan trọng
Server luôn là người bị động — nó không tự dưng gửi dữ liệu đến client. Nó chỉ phản hồi khi được hỏi. (Trừ khi dùng WebSocket — nhưng đó là câu chuyện của chương sau.)

1.3 HTTP — Ngôn ngữ của Web

HTTP (HyperText Transfer Protocol) là "ngôn ngữ" mà client và server dùng để nói chuyện. Mỗi cuộc trò chuyện gồm hai phần: Request (yêu cầu) và Response (phản hồi).

HTTP Request trông như thế này

        

          HTTP
          Ví dụ HTTP Request
          
        

        GET /api/products?category=phone HTTP/1.1
Host: shop.example.com
Accept: application/json
Authorization: Bearer eyJhbGci...
User-Agent: Mozilla/5.0 (Windows NT 10.0)

Giải thích từng dòng:

  • GET — phương thức HTTP (hành động muốn làm gì)
  • /api/products?category=phone — đường dẫn + query string
  • HTTP/1.1 — phiên bản giao thức
  • Host — tên miền đang gửi đến
  • Authorization — token xác thực (nếu có)

HTTP Response trông như thế này

        

          HTTP
          Ví dụ HTTP Response
          
        

        HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 248
Cache-Control: max-age=60

{
  "products": [
    { "id": 1, "name": "iPhone 15", "price": 25000000 },
    { "id": 2, "name": "Samsung S24", "price": 22000000 }
  ]
}

Giải thích:

  • 200 OK — status code, nghĩa là thành công
  • Content-Type: application/json — dữ liệu trả về là JSON
  • Dòng trống — phân cách header và body
  • Phần JSON bên dưới — body, dữ liệu thực sự

Các HTTP Methods phổ biến

Method Ý nghĩa Ví dụ thực tế
GET Lấy dữ liệu Xem danh sách sản phẩm
POST Tạo mới Đặt hàng, đăng ký tài khoản
PUT Cập nhật toàn bộ Sửa thông tin hồ sơ
PATCH Cập nhật một phần Đổi chỉ avatar
DELETE Xóa Xóa bài viết

HTTP Status Codes

Nhóm Ý nghĩa Ví dụ hay gặp
2xx Thành công ✅ 200 OK, 201 Created, 204 No Content
3xx Chuyển hướng 🔀 301 Moved, 302 Found
4xx Lỗi từ client ❌ 400 Bad Request, 401 Unauthorized, 404 Not Found
5xx Lỗi từ server 💥 500 Internal Server Error, 503 Service Unavailable

1.4 URL, Domain, IP và DNS

Khi bạn gõ https://facebook.com/profile/123 vào trình duyệt, URL đó có cấu trúc:

IP Address là gì?

Mỗi máy tính trên Internet có một địa chỉ IP (như số nhà). Ví dụ: 142.250.185.14 là một IP của Google. Nhưng nhớ số IP rất khó, nên chúng ta dùng domain name thay thế (như google.com).

DNS hoạt động như thế nào?

DNS (Domain Name System) như danh bạ điện thoại của Internet — nó dịch tên miền sang IP.

💡 Thử ngay
Mở Terminal/Command Prompt và gõ: nslookup google.com Bạn sẽ thấy IP address thực của Google.

1.5 HTTPS và SSL/TLS

HTTP truyền dữ liệu dưới dạng văn bản thuần — bất kỳ ai nghe giữa đường cũng đọc được. HTTPS thêm lớp mã hóa SSL/TLS: dữ liệu được mã hóa trước khi gửi đi, chỉ client và server mới đọc được.

HTTP HTTPS
Port mặc định 80 443
Mã hóa Không SSL/TLS
Dùng cho Dev local Mọi website thực tế

1.6 Frontend vs Backend

Khi bạn mở một trang web, có hai thế giới làm việc song song:

Frontend Backend
Chạy ở đâu Trình duyệt của người dùng Server
Ngôn ngữ HTML, CSS, JavaScript NodeJS, Python, Java, PHP…
Người dùng thấy Có (giao diện) Không (logic ẩn)
Làm gì Hiển thị, tương tác Xử lý, lưu dữ liệu, bảo mật
Ví dụ React, Vue, Angular Express, Django, Spring
📌 NodeJS là gì trong bức tranh này?
NodeJS cho phép bạn chạy JavaScript ở phía server. Trước khi có NodeJS, JavaScript chỉ chạy được trong trình duyệt. NodeJS "giải phóng" JavaScript ra khỏi trình duyệt — bạn dùng cùng một ngôn ngữ để viết cả frontend lẫn backend.

1.7 Code mẫu — Xem HTTP Request trong thực tế

Ví dụ 1: Dùng DevTools xem request

Mở Chrome, nhấn F12 → tab Network → tải trang bất kỳ. Bạn sẽ thấy hàng chục request hiện ra.

Ví dụ 2: Gửi HTTP request bằng JavaScript (fetch API)

        

          JavaScript
          fetch-example.js
          
        

        // Gửi GET request đến một API công khai
fetch('https://jsonplaceholder.typicode.com/posts/1')
  .then(response => {
    console.log('Status:', response.status);  // 200
    console.log('OK?', response.ok);           // true
    return response.json();
  })
  .then(data => {
    console.log('Dữ liệu nhận được:', data);
  })
  .catch(error => {
    console.error('Lỗi:', error);
  });

Kết quả khi chạy (trong DevTools Console hoặc NodeJS):

        

          Output
          
        

        Status: 200
OK? true
Dữ liệu nhận được: {
  id: 1,
  title: 'sunt aut facere repellat...',
  body: 'quia et suscipit...',
  userId: 1
}

Ví dụ 3: Gửi POST request với dữ liệu

        

          JavaScript
          post-example.js
          
        

        // Gửi POST request (tạo dữ liệu mới)
fetch('https://jsonplaceholder.typicode.com/posts', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',  // Báo server biết ta gửi JSON
  },
  body: JSON.stringify({                  // Chuyển object JS thành chuỗi JSON
    title: 'Bài viết mới',
    body: 'Nội dung bài viết...',
    userId: 1,
  }),
})
  .then(response => response.json())
  .then(data => {
    console.log('Tạo thành công:', data);
    // { id: 101, title: 'Bài viết mới', ... }
  });

Ví dụ 4: Xem raw HTTP bằng curl (Terminal)

        

          Shell
          Chạy trong Terminal
          
        

        # Xem toàn bộ HTTP request và response headers
curl -v https://jsonplaceholder.typicode.com/posts/1

# Kết quả sẽ hiện:
# > GET /posts/1 HTTP/2
# > Host: jsonplaceholder.typicode.com
# < HTTP/2 200
# < content-type: application/json; charset=utf-8
# { "userId": 1, "id": 1, ... }
⚠️ Lưu ý
curl có sẵn trên macOS và Linux. Trên Windows 10+, bạn cũng có thể dùng curl trong PowerShell hoặc Command Prompt. Nếu không có, cài curl.se hoặc dùng Postman.

1.8 Tóm tắt cơ chế hoạt động đầy đủ

Khi bạn gõ https://facebook.com và nhấn Enter, đây là điều xảy ra:

📚 Tóm tắt chương 1
  • Internet là hạ tầng mạng toàn cầu; Web là một dịch vụ chạy trên Internet
  • Client gửi request, Server trả response — đây là mô hình cơ bản của web
  • HTTP là giao thức giao tiếp: gồm method (GET/POST...), URL, headers, body và status code
  • DNS dịch tên miền thành IP address để máy tính có thể kết nối
  • HTTPS = HTTP + mã hóa SSL/TLS, luôn dùng cho production
  • Frontend chạy trong trình duyệt; Backend chạy trên server — NodeJS thuộc backend
🏋️ Bài tập thực hành
Dễ

1.1 Khám phá DevTools

Mở Chrome, vào trang bất kỳ (vd: vnexpress.net), nhấn F12 → tab Network. Reload trang và quan sát: Có bao nhiêu request được gửi đi? Request nào mất nhiều thời gian nhất? Click vào một request và xem Headers tab — ghi chép lại Status Code và Content-Type.

Dễ

1.2 Dùng fetch trong Console

Mở DevTools Console (F12 → Console). Copy và chạy ví dụ fetch ở mục 1.7. Thử thay đổi URL thành /posts/5 và xem kết quả thay đổi như thế nào. Thử gọi /posts/999 — status code là bao nhiêu?

Trung bình

1.3 Xây dựng hàm fetchData có error handling

Viết một hàm fetchData(url) nhận URL và trả về data. Hàm phải xử lý cả trường hợp lỗi mạng (catch) lẫn HTTP error (status code 4xx/5xx). Hint: response.ok là false khi status code >= 400.

Khó

1.4 Mini HTTP Inspector

Viết một trang HTML đơn giản có một ô input để nhập URL và một button "Gửi Request". Khi click, trang gửi GET request đến URL đó và hiển thị: status code, content-type header, và 500 ký tự đầu của response body. Thêm loading indicator khi đang chờ.
