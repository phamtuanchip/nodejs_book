Chương 9: Middleware và Error Handling

Middleware là trái tim của Express — mọi thứ từ authentication đến logging đến CORS đều là middleware. Hiểu middleware giúp bạn xây dựng ứng dụng có kiến trúc sạch và mở rộng được.

🎯 Sau chương này bạn sẽ biết
  • Middleware là gì và cơ chế next() hoạt động ra sao
  • Viết custom middleware: logger, request ID, authentication check
  • Dùng các middleware phổ biến: cors, helmet, morgan, express-rate-limit
  • Implement error handling middleware đúng chuẩn Express
  • Validate request body với Zod schema
  • Xử lý async errors an toàn với asyncHandler pattern

9.1 Middleware là gì?

Middleware là những function nằm giữa khi request đến và khi response được gửi về. Chúng tạo thành một pipeline (ống dẫn) — request đi qua từng middleware theo thứ tự, mỗi cái có thể đọc, sửa đổi request/response, hoặc dừng pipeline lại.

Mọi middleware trong Express đều có cùng chữ ký: 

JavaScriptCấu trúc middleware
// Middleware function signature
function myMiddleware(req, res, next) {
  // req  — request object (có thể đọc và sửa đổi)
  // res  — response object (có thể gửi response và dừng chain)
  // next — function để chuyển sang middleware tiếp theo

  // 3 lựa chọn:

  // 1. Gọi next() — chuyển sang middleware/handler tiếp theo
  next();

  // 2. Gửi response — kết thúc request-response cycle
  // res.json({ ... });

  // 3. Gọi next(error) — chuyển sang error handler
  // next(new Error('Something went wrong'));
}
📌 Quy tắc vàng của middleware
Mỗi middleware phải làm 1 trong 3 việc: gọi next(), gọi next(error), hoặc gửi response (res.json(), res.send()...). Nếu không làm gì trong 3 cái này, request sẽ bị treo mãi mãi và client timeout.

9.3 Viết Custom Middleware

Custom middleware là nơi bạn đặt logic tái sử dụng. Dưới đây là 3 middleware thực tế và hữu ích: 

JavaScriptmiddleware/requestLogger.js
/**
 * Middleware 1: Request Logger
 * Ghi log thời gian, method, path, và status code của mỗi request
 */
function requestLogger(req, res, next) {
  const start = Date.now();
  const timestamp = new Date().toISOString();

  // Ghi log khi request đến
  console.log(`→ [${timestamp}] ${req.method} ${req.url}`);

  // Hook vào sự kiện 'finish' của response để ghi log khi xong
  // res.on('finish') được gọi sau khi response đã được gửi
  res.on('finish', () => {
    const duration = Date.now() - start;
    const statusEmoji = res.statusCode < 400 ? '✅' : '❌';

    console.log(
      `← ${statusEmoji} [${res.statusCode}] ${req.method} ${req.url} ` +
      `(${duration}ms)`
    );
  });

  next(); // Chuyển sang middleware tiếp theo
}

module.exports = requestLogger;

const { randomUUID } = require('crypto');

/**
 * Middleware 2: Add Request ID
 * Tạo unique ID cho mỗi request — giúp tracing log khi debug
 */
function addRequestId(req, res, next) {
  // Dùng request-id từ client nếu có (useful cho distributed tracing)
  // Nếu không thì tự tạo mới
  req.id = req.get('X-Request-Id') || randomUUID();

  // Gắn ID vào response header để client biết
  res.set('X-Request-Id', req.id);

  next();
}

}

JavaScriptmiddleware/measureTime.js
/**
 * Middleware 4: Measure Processing Time
 * Gắn thời gian xử lý vào response header
 */
function measureTime(req, res, next) {
  const startHrTime = process.hrtime.bigint(); // Độ chính xác nanosecond

  res.on('finish', () => {
    const endHrTime = process.hrtime.bigint();
    const durationMs = Number(endHrTime - startHrTime) / 1_000_000; // Convert to ms

    // Ghi vào console
    console.log(`⏱️  ${req.method} ${req.path}: ${durationMs.toFixed(3)}ms`);

    // Gắn vào header để frontend có thể thấy (chỉ dùng khi dev)
    // res.set('X-Response-Time', `${durationMs.toFixed(2)}ms`);
    // Lưu ý: set header sau khi response đã gửi sẽ bị lỗi
    // Nên set header TRƯỚC khi gửi response
  });

  // Set header TRƯỚC khi response gửi
  const origJson = res.json.bind(res);
  res.json = function(body) {
    const endHrTime = process.hrtime.bigint();
    const durationMs = Number(endHrTime - startHrTime) / 1_000_000;
    res.set('X-Response-Time', `${durationMs.toFixed(2)}ms`);
    return origJson(body);
  };

  next();
}

9.4 Middleware phổ biến từ npm

Hầu hết các tính năng phổ biến đã có middleware sẵn trên npm, không cần tự viết lại từ đầu: 

BashTerminal

cors — Cross-Origin Resource Sharing

Mặc định, trình duyệt chặn request từ domain A đến API ở domain B (bảo mật same-origin policy). CORS là cách server "cho phép" các domain khác gọi API của mình. 

JavaScriptcors-config.js
const cors = require('cors');

// ── Option 1: Cho phép TẤT CẢ origins (không an toàn cho production)
app.use(cors());

// ── Option 2: Chỉ cho phép domain cụ thể
app.use(cors({
  origin: 'https://myapp.com'
}));

// ── Option 3: Config đầy đủ cho production
const corsOptions = {
  // Danh sách origins được phép
  origin: function(origin, callback) {
    const allowedOrigins = [
      'https://myapp.com',
      'https://www.myapp.com',
      'http://localhost:3000',  // Development
      'http://localhost:5173',  // Vite dev server
    ];

    // Cho phép request không có origin (vd: Postman, curl, mobile app)
    if (!origin) return callback(null, true);

    if (allowedOrigins.includes(origin)) {
      callback(null, true);
    } else {
      callback(new Error(`CORS: Origin ${origin} không được phép`));
    }
  },

  methods: ['GET', 'POST', 'PUT', 'PATCH', 'DELETE', 'OPTIONS'],
  allowedHeaders: ['Content-Type', 'Authorization', 'X-API-Key'],
  exposedHeaders: ['X-Request-Id', 'X-Rate-Limit-Remaining'],
  credentials: true,   // Cho phép gửi cookies và Authorization header
  maxAge: 86400,       // Cache preflight request 24 giờ (giảm OPTIONS requests)
};

app.use(cors(corsOptions));

// ── Áp dụng CORS cho route cụ thể ──
app.get('/public-api', cors(), (req, res) => {
  // Chỉ route này cho phép tất cả origins
  res.json({ public: true });
});

helmet — Security Headers

Helmet tự động thêm hơn 15 HTTP security headers vào mọi response, bảo vệ app khỏi các lỗ hổng phổ biến như XSS, clickjacking, MIME sniffing... 

JavaScripthelmet-config.js
const helmet = require('helmet');

// Cách đơn giản nhất — dùng mặc định (đủ tốt cho hầu hết app)
app.use(helmet());

// Headers helmet thêm vào:
// Content-Security-Policy        — Kiểm soát tài nguyên được load
// X-Frame-Options: SAMEORIGIN   — Chống clickjacking (iframe embedding)
// X-Content-Type-Options: nosniff — Chống MIME sniffing
// Strict-Transport-Security      — Bắt buộc dùng HTTPS (HSTS)
// X-XSS-Protection               — Bật XSS filter của browser
// Referrer-Policy                — Kiểm soát thông tin referrer
// ... và nhiều header khác

// Config nâng cao nếu cần
app.use(helmet({
  contentSecurityPolicy: {
    directives: {
      defaultSrc: ["'self'"],
      scriptSrc: ["'self'", "'unsafe-inline'", 'cdn.example.com'],
      styleSrc: ["'self'", "'unsafe-inline'", 'fonts.googleapis.com'],
      imgSrc: ["'self'", 'data:', 'https:'],
      fontSrc: ["'self'", 'fonts.gstatic.com'],
    }
  },
  // Tắt một header cụ thể nếu gây conflict:
  // xFrameOptions: false,
  crossOriginEmbedderPolicy: false, // Tắt nếu dùng CDN resources
}));

morgan — HTTP Request Logging

JavaScriptmorgan-config.js
const morgan = require('morgan');
const fs = require('fs');
const path = require('path');

// ── Format sẵn có ──
// 'combined' — Apache combined log format (dùng cho production)
// 'common'   — Apache common log format
// 'dev'      — Màu sắc, ngắn gọn (dùng khi development)
// 'tiny'     — Rất ngắn
// 'short'    — Ngắn gọn, có response time

// Development: log ra console với màu sắc
if (process.env.NODE_ENV !== 'production') {
  app.use(morgan('dev'));
  // Output: GET /api/products 200 15.234 ms - 234
}

// Production: log ra file
if (process.env.NODE_ENV === 'production') {
  // Tạo thư mục logs nếu chưa có
  const logsDir = path.join(__dirname, 'logs');
  if (!fs.existsSync(logsDir)) fs.mkdirSync(logsDir, { recursive: true });

  // Stream ghi ra file
  const accessLogStream = fs.createWriteStream(
    path.join(logsDir, 'access.log'),
    { flags: 'a' } // append mode
  );

  app.use(morgan('combined', { stream: accessLogStream }));
}

// ── Custom Token ── Thêm thông tin custom vào log
morgan.token('request-id', (req) => req.id || '-');
morgan.token('body-size', (req) => {
  const body = JSON.stringify(req.body);
  return body ? `${body.length}B` : '-';
});

// Format custom
app.use(morgan('[:date[clf]] ":method :url" :status :response-time ms - :request-id'));

// ── Bỏ qua log health check (giảm noise) ──
app.use(morgan('dev', {
  skip: (req) => req.path === '/health' || req.path === '/favicon.ico'
}));

express-rate-limit — Giới hạn số request

JavaScriptrate-limit-config.js
const rateLimit = require('express-rate-limit');

// ── Rate limit tổng quát cho toàn app ──
const globalLimiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15 phút
  max: 200,                  // Tối đa 200 requests / 15 phút / IP
  standardHeaders: true,     // Thêm RateLimit-* headers vào response
  legacyHeaders: false,      // Tắt X-RateLimit-* headers cũ
  message: {
    success: false,
    error: 'Quá nhiều request từ IP này. Thử lại sau 15 phút.',
  }
});

app.use(globalLimiter); // Áp dụng cho tất cả

// ── Rate limit chặt hơn cho endpoint nhạy cảm ──
const loginLimiter = rateLimit({
  windowMs: 60 * 60 * 1000, // 1 giờ
  max: 5,                    // Chỉ 5 lần login thất bại / giờ / IP
  skipSuccessfulRequests: true, // Không đếm request thành công (chỉ đếm lỗi)
  message: {
    success: false,
    error: 'Quá nhiều lần đăng nhập thất bại. Tài khoản bị tạm khóa 1 giờ.',
  }
});

app.post('/api/auth/login', loginLimiter, authController.login);

// ── Rate limit cho API (dùng API key) ──
const apiLimiter = rateLimit({
  windowMs: 60 * 1000,  // 1 phút
  max: 60,              // 60 requests/phút (1 request/giây)
  keyGenerator: (req) => {
    // Rate limit theo API key thay vì IP
    return req.get('X-API-Key') || req.ip;
  },
});

9.5 Error Handling Middleware

Error handling là một trong những phần quan trọng nhất — ứng dụng production phải xử lý lỗi một cách có kiểm soát, không để lộ thông tin nhạy cảm, và luôn trả về response có cấu trúc nhất quán. 

JavaScripterrors/AppError.js
/**
 * Custom Error class cho ứng dụng
 * Mở rộng Error mặc định với statusCode và các thông tin thêm
 */
class AppError extends Error {
  constructor(message, statusCode = 500, details = null) {
    super(message);          // Gọi Error constructor với message
    this.name = 'AppError';  // Tên lỗi
    this.statusCode = statusCode;
    this.details = details;  // Thông tin thêm (vd: validation errors)
    this.isOperational = true; // Lỗi có chủ ý (ko phải bug bất ngờ)

    // Ghi lại stack trace
    Error.captureStackTrace(this, this.constructor);
  }

  // Factory methods tiện lợi
  static badRequest(message, details) {
    return new AppError(message, 400, details);
  }

  static unauthorized(message = 'Chưa đăng nhập hoặc token hết hạn') {
    return new AppError(message, 401);
  }

  static forbidden(message = 'Không có quyền truy cập') {
    return new AppError(message, 403);
  }

  static notFound(resource = 'Tài nguyên') {
    return new AppError(`${resource} không tìm thấy`, 404);
  }

  static conflict(message) {
    return new AppError(message, 409);
  }

  static tooManyRequests(message = 'Quá nhiều request') {
    return new AppError(message, 429);
  }
}

module.exports = AppError;
JavaScriptmiddleware/errorHandler.js
const AppError = require('../errors/AppError');

/**
 * Global Error Handler Middleware
 * PHẢI có đúng 4 tham số (err, req, res, next)
 * PHẢI đặt SAU TẤT CẢ route handlers và middleware khác
 */
function errorHandler(err, req, res, next) {
  // Log lỗi ra console (trong production nên dùng logging service)
  if (process.env.NODE_ENV === 'development') {
    console.error('🔴 Error:', err);
  } else {
    // Production: chỉ log lỗi không mong đợi
    if (!err.isOperational) {
      console.error('🔴 Unexpected error:', err);
    }
  }

  // Xử lý các loại lỗi phổ biến từ thư viện bên ngoài
  let error = err;

  // Mongoose: CastError (ID không đúng format)
  if (err.name === 'CastError') {
    error = AppError.badRequest(`Giá trị "${err.value}" không hợp lệ cho field ${err.path}`);
  }

  // Mongoose: Duplicate key (E11000)
  if (err.code === 11000) {
    const field = Object.keys(err.keyValue)[0];
    error = AppError.conflict(`${field} "${err.keyValue[field]}" đã tồn tại`);
  }

  // Zod: Validation error
  if (err.name === 'ZodError') {
    const errors = err.errors.map(e => ({
      field: e.path.join('.'),
      message: e.message
    }));
    error = AppError.badRequest('Dữ liệu không hợp lệ', errors);
  }

  // JWT: Token lỗi
  if (err.name === 'JsonWebTokenError') {
    error = AppError.unauthorized('Token không hợp lệ');
  }
  if (err.name === 'TokenExpiredError') {
    error = AppError.unauthorized('Token đã hết hạn, vui lòng đăng nhập lại');
  }

  // Express: Body too large
  if (err.type === 'entity.too.large') {
    error = AppError.badRequest('Request body quá lớn');
  }

  // Chuẩn bị response
  const statusCode = error.statusCode || 500;
  const response = {
    success: false,
    error: {
      message: error.message || 'Lỗi server nội bộ',
      ...(error.details && { details: error.details }),
    },
    requestId: req.id, // Từ addRequestId middleware
  };

  // Trong development: thêm stack trace
  if (process.env.NODE_ENV === 'development') {
    response.error.stack = err.stack;
  }

  res.status(statusCode).json(response);
}

JavaScriptmiddleware/validate.js
/**
 * Middleware factory: validate request với Zod schema
 *
 * @param {Object} schemas - { body?, query?, params? }
 * @returns Express middleware
 *
 * Cách dùng:
 *   router.post('/', validate({ body: createPostSchema }), handler)
 *   router.get('/', validate({ query: paginationSchema }), handler)
 */
function validate(schemas) {
  return (req, res, next) => {
    const errors = [];

    try {
      // Validate từng phần của request
      if (schemas.body) {
        const result = schemas.body.safeParse(req.body);
        if (!result.success) {
          result.error.errors.forEach(e => {
            errors.push({ location: 'body', field: e.path.join('.'), message: e.message });
          });
        } else {
          req.body = result.data; // Replace với data đã được transform
        }
      }

      if (schemas.query) {
        const result = schemas.query.safeParse(req.query);
        if (!result.success) {
          result.error.errors.forEach(e => {
            errors.push({ location: 'query', field: e.path.join('.'), message: e.message });
          });
        } else {
          req.query = result.data;
        }
      }

      if (schemas.params) {
        const result = schemas.params.safeParse(req.params);
        if (!result.success) {
          result.error.errors.forEach(e => {
            errors.push({ location: 'params', field: e.path.join('.'), message: e.message });
          });
        } else {
          req.params = result.data;
        }
      }

      if (errors.length > 0) {
        return res.status(400).json({
          success: false,
          error: 'Dữ liệu không hợp lệ',
          details: errors,
        });
      }

      next();
    } catch (err) {
      next(err);
    }
  };
}

module.exports = validate;

9.7 Async Middleware và Route Handlers

Đây là một lỗi rất phổ biến: khi dùng async/await trong route handler, nếu có lỗi bị throw, nó KHÔNG tự động đi đến error handler. Bạn phải tự bắt lỗi: 

JavaScriptasync-error-problem.js
// ❌ SAI: Lỗi không đến error handler, app bị crash!
app.get('/users/:id', async (req, res) => {
  const user = await User.findById(req.params.id); // Lỗi DB → crash!
  res.json(user);
});

// ✅ CÁCH 1: try/catch thủ công (an toàn nhưng verbose)
app.get('/users/:id', async (req, res, next) => {
  try {
    const user = await User.findById(req.params.id);
    if (!user) return res.status(404).json({ error: 'Not found' });
    res.json(user);
  } catch (err) {
    next(err); // Chuyển lỗi đến error handler
  }
});

// ✅ CÁCH 2: asyncHandler wrapper (sạch hơn, recommend)
const asyncHandler = (fn) => (req, res, next) => {
  Promise.resolve(fn(req, res, next)).catch(next);
  // Nếu fn throw hoặc promise reject → next(err) được gọi tự động
};

// Dùng:
app.get('/users/:id', asyncHandler(async (req, res) => {
  const user = await User.findById(req.params.id); // Lỗi → next(err) tự động!
  if (!user) throw AppError.notFound('User');
  res.json({ success: true, data: user });
}));

/**
 * asyncHandler — Wrap async function để tự động catch lỗi
 * và chuyển đến Express error handler
 *
 * Không cần try/catch trong mọi route handler nữa!
 */
const asyncHandler = (fn) => {
  return function asyncHandlerWrapper(req, res, next) {
    return Promise.resolve(fn(req, res, next)).catch(next);
  };
};

9.1 Middleware đo thời gian xử lý

Viết middleware measureTime ghi ra console thời gian xử lý của mỗi request theo format: [METHOD] /path → Xms (STATUS). Middleware phải dùng process.hrtime.bigint() để đo chính xác đến millisecond. Gắn thêm header X-Response-Time vào response. Test với ít nhất 3 routes khác nhau.

9.2 Cache middleware với TTL

Viết middleware factory cacheResponse(seconds) — lưu response vào Map với key là URL. Nếu request đến và cache còn hạn, trả về cached version kèm header X-Cache: HIT. Nếu hết hạn hoặc chưa có, xử lý bình thường và cache kết quả với header X-Cache: MISS. Lưu ý: chỉ cache GET requests và status 200. Test: app.get('/api/products', cacheResponse(30), handler).

9.3 Request Sanitizer Middleware

Xây dựng middleware requestSanitizer(options) tự động:

  • Trim strings: xóa whitespace đầu/cuối tất cả string values trong req.body
  • Chặn XSS: xóa HTML tags (thay <script>, <img>... bằng chuỗi rỗng) dùng regex
  • Validate content-length: reject nếu body lớn hơn options.maxSize bytes
  • Field whitelist: reject request nếu body chứa fields không nằm trong options.allowedFields

Middleware phải hoạt động đệ quy với nested objects và arrays. Viết test cases cho từng tính năng.
