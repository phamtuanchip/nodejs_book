Chương 10: Cookie, Session và Authentication

10.1 Cookie với Express

Cookie là các cặp key-value nhỏ mà server yêu cầu browser lưu trữ và tự động gửi kèm trong mọi request tiếp theo. Đây là nền tảng của trạng thái trong HTTP — một giao thức vốn dĩ stateless.

Để làm việc với cookie trong Express, cài thêm cookie-parser — một middleware tự động parse Cookie header thành object req.cookies. 

        

          Shell
          Terminal
          
        

        npm install express cookie-parser
      
        

          JavaScript
          app.js — Thiết lập cookie-parser
          
        

        const express = require('express');
const cookieParser = require('cookie-parser');

const app = express();

// Đăng ký middleware cookie-parser
// 'mySecretKey' dùng để ký signed cookies (tùy chọn)
app.use(cookieParser('mySecretKey'));

// SET COOKIE: lưu tùy chọn giao diện người dùng
app.post('/preferences', (req, res) => {
  const { theme, language } = req.body;

  res.cookie('theme', theme, {
    maxAge: 30 * 24 * 60 * 60 * 1000, // 30 ngày (milliseconds)
    httpOnly: false,                    // JS frontend có thể đọc
    secure: process.env.NODE_ENV === 'production', // chỉ HTTPS khi production
    sameSite: 'lax',                    // bảo vệ CSRF một phần
  });

  res.cookie('lang', language, {
    maxAge: 30 * 24 * 60 * 60 * 1000,
    httpOnly: false,
    sameSite: 'lax',
  });

  res.json({ message: 'Đã lưu tùy chọn' });
});

// READ COOKIE: đọc tùy chọn đã lưu
app.get('/preferences', (req, res) => {
  const theme = req.cookies.theme || 'light';
  const lang  = req.cookies.lang  || 'vi';

  res.json({ theme, lang });
});

// CLEAR COOKIE: xóa một cookie cụ thể
app.delete('/preferences', (req, res) => {
  res.clearCookie('theme');
  res.clearCookie('lang');
  res.json({ message: 'Đã xóa tùy chọn' });
});

Các options cookie quan trọng

Option Giá trị mẫu Mục đích
httpOnly true JavaScript phía client không thể đọc cookie — ngăn XSS đánh cắp token
secure true Chỉ gửi cookie qua HTTPS — không gửi qua HTTP thường
sameSite 'strict' / 'lax' / 'none' Kiểm soát khi nào cookie được gửi trong cross-site requests — bảo vệ CSRF
maxAge 86400000 Thời gian sống tính bằng milliseconds (86400000 = 1 ngày)
expires new Date(...) Ngày hết hạn tuyệt đối — dùng maxAge hoặc expires, không dùng cả hai
domain '.example.com' Cookie chia sẻ được giữa subdomains (app.example.com, api.example.com)
path '/' Cookie chỉ gửi khi URL bắt đầu bằng path này
signed true Ký cookie bằng secret — phát hiện nếu client tự ý sửa giá trị
Bảo mật cookie
Luôn bật httpOnly: true cho cookie chứa session ID hoặc token xác thực. Cookie không có httpOnly có thể bị đọc bởi script XSS, dẫn đến chiếm tài khoản. Ngoài ra, secure: true phải bật trên production để chặn đánh cắp cookie qua mạng không mã hóa.

10.2 Server Session với express-session

Cookie lưu dữ liệu trực tiếp trong trình duyệt. Session thì khác: server chỉ gửi cho browser một chuỗi ID ngẫu nhiên (session ID), còn dữ liệu thực sự được lưu trên server. Browser chỉ biết cái ID, không biết nội dung. 

        

          Shell
          Terminal
          
        

        npm install express-session
      
        

          JavaScript
          app.js — Cấu hình express-session
          
        

        const session = require('express-session');

app.use(session({
  secret: process.env.SESSION_SECRET || 'dev-secret-change-in-production',
  resave: false,           // không lưu lại session nếu không thay đổi
  saveUninitialized: false, // không tạo session cho request chưa đăng nhập
  cookie: {
    httpOnly: true,
    secure: process.env.NODE_ENV === 'production',
    maxAge: 24 * 60 * 60 * 1000, // 1 ngày
    sameSite: 'lax',
  },
}));

// Dữ liệu người dùng giả (không cần DB)
const users = [
  { id: 1, email: 'alice@example.com', password: 'hashed_pw_1', name: 'Alice' },
  { id: 2, email: 'bob@example.com',   password: 'hashed_pw_2', name: 'Bob'   },
];

// POST /login — đăng nhập bằng session
app.post('/login', express.json(), (req, res) => {
  const { email, password } = req.body;

  // Tìm user (trong thực tế sẽ dùng bcrypt.compare)
  const user = users.find(u => u.email === email);
  if (!user || password !== 'secret123') {
    return res.status(401).json({ error: 'Email hoặc mật khẩu không đúng' });
  }

  // Lưu thông tin vào session — object này tồn tại trên SERVER
  req.session.userId   = user.id;
  req.session.userName = user.name;
  req.session.loginAt  = new Date().toISOString();

  res.json({ message: `Chào mừng ${user.name}!` });
});

// GET /profile — lấy thông tin người dùng từ session
app.get('/profile', (req, res) => {
  if (!req.session.userId) {
    return res.status(401).json({ error: 'Chưa đăng nhập' });
  }

  const user = users.find(u => u.id === req.session.userId);
  res.json({
    name:    user.name,
    email:   user.email,
    loginAt: req.session.loginAt,
  });
});

// POST /logout — hủy session
app.post('/logout', (req, res) => {
  req.session.destroy(err => {
    if (err) return res.status(500).json({ error: 'Không thể đăng xuất' });

    res.clearCookie('connect.sid'); // tên mặc định của session cookie
    res.json({ message: 'Đã đăng xuất thành công' });
  });
});
MemoryStore — Chỉ dùng cho development
Theo mặc định, express-session lưu session trong RAM (MemoryStore). Điều này có nghĩa là: mỗi khi restart server, tất cả session bị xóa; và khi scale lên nhiều server, mỗi server có session riêng — user đăng nhập ở server 1 sẽ bị logout khi request tới server 2. Trong production, dùng connect-redis hoặc connect-mongo để lưu session vào database dùng chung.

10.3 Hash Password với bcrypt

Không bao giờ lưu mật khẩu dạng plain text. Nếu database bị tấn công, toàn bộ mật khẩu của người dùng bị lộ. Nhưng tại sao không dùng MD5 hay SHA-256 thông thường?

Vấn đề với MD5 và SHA-256 cho password

  • Quá nhanh: GPU hiện đại có thể hash hàng tỷ SHA-256 mỗi giây. Attacker có thể brute-force toàn bộ dictionary trong vài giờ.
  • Rainbow table: Bảng hash đã tính sẵn của hàng triệu mật khẩu phổ biến. md5('123456') luôn cho cùng một kết quả.
  • Không có salt: Hai người dùng cùng mật khẩu sẽ có cùng hash — lộ một lộ tất cả.

bcrypt giải quyết tất cả: nó cố tình chậm (có thể điều chỉnh), tự sinh salt ngẫu nhiên, và salt được nhúng vào trong chuỗi hash kết quả. 

        

          Shell
          Terminal
          
        

        # bcryptjs = pure JavaScript, không cần build native addon
# bcrypt   = native C++ binding, nhanh hơn nhưng cần build tools
npm install bcryptjs
      
        

          JavaScript
          auth/password.js — Hash và verify password
          
        

        const bcrypt = require('bcryptjs');

// ============ HASH PASSWORD ============
// saltRounds = "cost factor" — số vòng lặp = 2^saltRounds
// saltRounds 10 → ~100ms/hash; 12 → ~400ms/hash; 14 → ~1.5s/hash
// Production khuyến nghị: 10-12

const saltRounds = 12;

async function hashPassword(plainPassword) {
  // bcrypt.hash tự sinh salt, hash, và gộp thành một chuỗi:
  // $2b$12$[22 ký tự salt][31 ký tự hash]
  const hash = await bcrypt.hash(plainPassword, saltRounds);
  return hash;
}

// ============ VERIFY PASSWORD ============
async function verifyPassword(plainPassword, storedHash) {
  // bcrypt.compare đọc salt từ storedHash, hash lại plainPassword,
  // rồi so sánh — trả về true/false
  const isMatch = await bcrypt.compare(plainPassword, storedHash);
  return isMatch;
}

// ============ DEMO ============
async function demo() {
  const password = 'MySecurePassword123!';

  console.log('Đang hash...');
  const hash = await hashPassword(password);
  console.log('Hash:', hash);
  // Ví dụ: $2b$12$LQv3c1yqBWVHxkd0LHAkCOYz6TtxMQJqhN8/NekdBnj6q20UvE6Vy

  console.log('\nKiểm tra mật khẩu đúng:');
  console.log(await verifyPassword(password, hash));     // true

  console.log('\nKiểm tra mật khẩu sai:');
  console.log(await verifyPassword('sai_password', hash)); // false

  // Mỗi lần hash cho kết quả KHÁC NHAU do salt ngẫu nhiên
  const hash2 = await hashPassword(password);
  console.log('\nHash lần 2 (salt khác):', hash !== hash2); // true
}

demo();
      
        

          JavaScript
          routes/auth.js — Đăng ký và đăng nhập với bcrypt
          
        

        const express = require('express');
const bcrypt  = require('bcryptjs');
const router  = express.Router();

// In-memory store (thay bằng database trong thực tế)
const users = new Map(); // key: email, value: { id, email, name, passwordHash }
let nextId = 1;

// POST /auth/register
router.post('/register', async (req, res) => {
  try {
    const { name, email, password } = req.body;

    // Validation cơ bản
    if (!name || !email || !password)
      return res.status(400).json({ error: 'Vui lòng điền đầy đủ thông tin' });
    if (password.length < 8)
      return res.status(400).json({ error: 'Mật khẩu tối thiểu 8 ký tự' });
    if (users.has(email))
      return res.status(409).json({ error: 'Email đã được đăng ký' });

    const passwordHash = await bcrypt.hash(password, 12);

    const user = { id: nextId++, name, email, passwordHash };
    users.set(email, user);

    // Không trả về passwordHash
    res.status(201).json({ message: 'Đăng ký thành công', userId: user.id });
  } catch (err) {
    res.status(500).json({ error: 'Lỗi server: ' + err.message });
  }
});

// POST /auth/login
router.post('/login', async (req, res) => {
  try {
    const { email, password } = req.body;

    const user = users.get(email);
    // Luôn gọi bcrypt.compare kể cả khi user không tồn tại
    // để tránh timing attack (so sánh thời gian phản hồi)
    const fakeHash = '$2b$12$invalidhashfortimingprotection000000000000000000000000000';
    const isMatch = user
      ? await bcrypt.compare(password, user.passwordHash)
      : await bcrypt.compare(password, fakeHash);

    if (!user || !isMatch) {
      return res.status(401).json({ error: 'Email hoặc mật khẩu không đúng' });
    }

    req.session.userId = user.id;
    res.json({ message: `Chào mừng, ${user.name}!` });
  } catch (err) {
    res.status(500).json({ error: 'Lỗi server: ' + err.message });
  }
});

module.exports = router;

10.4 JWT Authentication

JSON Web Token (JWT) là một cách khác để xác thực người dùng — không cần lưu session trên server. Thay vào đó, server tạo một token có chứa thông tin user và chữ ký mật mã. Client lưu token này và gửi kèm mỗi request.

Cấu trúc JWT

JWT gồm 3 phần phân cách bằng dấu chấm: Header.Payload.Signature

        

          Text
          Ví dụ JWT token
          
        

        eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9         ← Header (base64url)
.eyJ1c2VySWQiOjEsImVtYWlsIjoiYWxpY2VAZXhhbXBsZS5jb20iLCJpYXQiOjE2OTAwMDAwMDAsImV4cCI6MTY5MDYwNDgwMH0=  ← Payload (base64url)
.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c        ← Signature (HMAC-SHA256)

// Payload sau khi decode:
{
  "userId": 1,
  "email": "alice@example.com",
  "iat": 1690000000,   // issued at
  "exp": 1690604800    // expiration
}
Payload không bí mật
Phần Payload của JWT chỉ được encode bằng base64url — không phải mã hóa. Bất kỳ ai cũng có thể đọc nội dung. Chỉ có Signature là được ký bằng secret key. Đừng bao giờ đặt thông tin nhạy cảm (password, thẻ tín dụng) vào payload. 
        

          Shell
          Terminal
          
        

        npm install jsonwebtoken
      
        

          JavaScript
          utils/jwt.js — Tạo và xác minh JWT
          
        

        const jwt = require('jsonwebtoken');

const ACCESS_TOKEN_SECRET  = process.env.JWT_ACCESS_SECRET  || 'access-secret-dev';
const REFRESH_TOKEN_SECRET = process.env.JWT_REFRESH_SECRET || 'refresh-secret-dev';

// Tạo access token (ngắn hạn)
function signAccessToken(payload) {
  return jwt.sign(payload, ACCESS_TOKEN_SECRET, {
    expiresIn: '15m', // 15 phút
    algorithm: 'HS256',
  });
}

// Tạo refresh token (dài hạn)
function signRefreshToken(payload) {
  return jwt.sign(payload, REFRESH_TOKEN_SECRET, {
    expiresIn: '30d', // 30 ngày
    algorithm: 'HS256',
  });
}

// Xác minh access token
function verifyAccessToken(token) {
  try {
    return jwt.verify(token, ACCESS_TOKEN_SECRET);
    // Trả về payload nếu hợp lệ
    // Throw JsonWebTokenError nếu chữ ký sai
    // Throw TokenExpiredError nếu hết hạn
  } catch (err) {
    return null; // Token không hợp lệ
  }
}

// Xác minh refresh token
function verifyRefreshToken(token) {
  try {
    return jwt.verify(token, REFRESH_TOKEN_SECRET);
  } catch (err) {
    return null;
  }
}

module.exports = {
  signAccessToken,
  signRefreshToken,
  verifyAccessToken,
  verifyRefreshToken,
};

Lưu JWT ở đâu — localStorage vs httpOnly cookie

Cách lưu Ưu điểm Rủi ro
localStorage Dễ gửi kèm request, không bị giới hạn subdomain Dễ bị đánh cắp bởi XSS — bất kỳ script nào cũng đọc được
sessionStorage Tự xóa khi đóng tab Vẫn dễ bị XSS; mất khi tab đóng — không tiện lợi
httpOnly cookie JS không đọc được → XSS không lấy được token Cần xử lý CSRF; không hoạt động với mobile app native

Khuyến nghị: lưu access token trong memory (biến JS) và refresh token trong httpOnly cookie. Khi trang tải lại, dùng refresh token để lấy access token mới.

10.5 Auth Middleware

Middleware xác thực đọc token từ request, xác minh tính hợp lệ, và nếu hợp lệ thì đính kèm thông tin user vào req.user để các handler sau sử dụng. 

        

          JavaScript
          middlewares/auth.js — Auth middleware đầy đủ
          
        

        const jwt = require('jsonwebtoken');

const ACCESS_TOKEN_SECRET = process.env.JWT_ACCESS_SECRET || 'access-secret-dev';

// ============ HELPER: asyncHandler ============
// Bọc async function để tự động truyền lỗi sang next()
const asyncHandler = fn => (req, res, next) => {
  Promise.resolve(fn(req, res, next)).catch(next);
};

// ============ CLASS LỖI TÙY CHỈNH ============
class AppError extends Error {
  constructor(message, statusCode) {
    super(message);
    this.statusCode = statusCode;
  }
}

// ============ AUTH MIDDLEWARE (bắt buộc) ============
const authMiddleware = asyncHandler(async (req, res, next) => {
  // Đọc token từ Authorization header hoặc cookie
  let token;
  const authHeader = req.headers.authorization;

  if (authHeader && authHeader.startsWith('Bearer ')) {
    token = authHeader.split(' ')[1];
  } else if (req.cookies?.access_token) {
    token = req.cookies.access_token;
  }

  if (!token) {
    throw new AppError('Chưa đăng nhập — vui lòng cung cấp token', 401);
  }

  let decoded;
  try {
    decoded = jwt.verify(token, ACCESS_TOKEN_SECRET);
  } catch (err) {
    if (err.name === 'TokenExpiredError') {
      throw new AppError('Token đã hết hạn — vui lòng refresh', 401);
    }
    throw new AppError('Token không hợp lệ', 401);
  }

  // Đính kèm user info vào request để dùng ở handler
  req.user = decoded; // { userId, email, role, iat, exp }
  next();
});

// ============ OPTIONAL AUTH MIDDLEWARE ============
// Không fail nếu không có token; chỉ đính kèm user nếu token hợp lệ
const optionalAuth = (req, res, next) => {
  const authHeader = req.headers.authorization;
  const token = authHeader?.startsWith('Bearer ')
    ? authHeader.split(' ')[1]
    : req.cookies?.access_token;

  if (!token) return next(); // Tiếp tục mà không có user

  try {
    req.user = jwt.verify(token, ACCESS_TOKEN_SECRET);
  } catch {
    // Token không hợp lệ → bỏ qua, không fail
  }
  next();
};

// ============ ROLE-BASED MIDDLEWARE FACTORY ============
// Dùng: router.get('/admin', authMiddleware, requireRole('admin'), handler)
// Hoặc: router.get('/mod', authMiddleware, requireRole(['admin', 'moderator']), handler)
const requireRole = (roles) => {
  const allowed = Array.isArray(roles) ? roles : [roles];
  return (req, res, next) => {
    if (!req.user) {
      return res.status(401).json({ error: 'Chưa xác thực' });
    }
    if (!allowed.includes(req.user.role)) {
      return res.status(403).json({
        error: `Không có quyền — yêu cầu role: ${allowed.join(', ')}`,
      });
    }
    next();
  };
};

module.exports = { authMiddleware, optionalAuth, requireRole, AppError, asyncHandler };
      
        

          JavaScript
          routes/protected.js — Sử dụng auth middleware
          
        

        const express = require('express');
const { authMiddleware, requireRole } = require('../middlewares/auth');
const router = express.Router();

// Áp dụng authMiddleware cho tất cả routes trong file này
router.use(authMiddleware);

// Route bình thường — chỉ cần đăng nhập
router.get('/dashboard', (req, res) => {
  res.json({
    message: `Xin chào ${req.user.email}`,
    userId:  req.user.userId,
  });
});

// Route cần role admin
router.get('/admin/users', requireRole('admin'), (req, res) => {
  res.json({ users: [/* danh sách users */] });
});

// Route cho nhiều roles
router.delete('/posts/:id', requireRole(['admin', 'moderator']), (req, res) => {
  res.json({ message: `Đã xóa bài ${req.params.id}` });
});

module.exports = router;

10.6 Refresh Token Pattern

Access token có vòng đời ngắn (15 phút) để giảm rủi ro nếu bị đánh cắp. Refresh token có vòng đời dài (30 ngày) và được lưu trong httpOnly cookie — client dùng nó để lấy access token mới mà không cần đăng nhập lại. 

        

          JavaScript
          routes/auth.js — Refresh token endpoint
          
        

        const { signAccessToken, verifyRefreshToken } = require('../utils/jwt');

// POST /auth/refresh
router.post('/refresh', (req, res) => {
  const refreshToken = req.cookies.refresh_token;

  if (!refreshToken) {
    return res.status(401).json({ error: 'Không có refresh token' });
  }

  const decoded = verifyRefreshToken(refreshToken);
  if (!decoded) {
    // Xóa cookie không hợp lệ
    res.clearCookie('refresh_token');
    return res.status(401).json({ error: 'Refresh token không hợp lệ hoặc đã hết hạn' });
  }

  // Tạo access token mới
  const newAccessToken = signAccessToken({
    userId: decoded.userId,
    email:  decoded.email,
    role:   decoded.role,
  });

  res.json({ accessToken: newAccessToken });
});

// POST /auth/logout — Xóa refresh token cookie
router.post('/logout', (req, res) => {
  res.clearCookie('refresh_token', {
    httpOnly: true,
    secure:   process.env.NODE_ENV === 'production',
    sameSite: 'lax',
  });
  res.json({ message: 'Đăng xuất thành công' });
});

10.7 Dự án: Hệ thống Authentication Hoàn chỉnh

          routes/auth.js — Tất cả auth routes
          
        

        const express  = require('express');
const bcrypt   = require('bcryptjs');
const router   = express.Router();
const userStore = require('../store/users');
const { signAccessToken, signRefreshToken, verifyRefreshToken } = require('../utils/jwt');
const { authMiddleware } = require('../middlewares/auth');

const COOKIE_OPTIONS = {
  httpOnly: true,
  secure:   process.env.NODE_ENV === 'production',
  sameSite: 'lax',
  maxAge:   30 * 24 * 60 * 60 * 1000, // 30 ngày
};

// ────────────────────────────────────────────
// POST /auth/register
// ────────────────────────────────────────────
router.post('/register', async (req, res) => {
  try {
    const { name, email, password } = req.body;

    if (!name?.trim() || !email?.trim() || !password)
      return res.status(400).json({ error: 'Vui lòng điền đầy đủ: tên, email, mật khẩu' });

    if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email))
      return res.status(400).json({ error: 'Định dạng email không hợp lệ' });

    if (password.length < 8)
      return res.status(400).json({ error: 'Mật khẩu tối thiểu 8 ký tự' });

    if (userStore.findByEmail(email))
      return res.status(409).json({ error: 'Email đã được đăng ký' });

    const passwordHash = await bcrypt.hash(password, 12);
    const user = userStore.create({ name: name.trim(), email: email.toLowerCase(), passwordHash, role: 'user' });

    const accessToken  = signAccessToken({ userId: user.id, email: user.email, role: user.role });
    const refreshToken = signRefreshToken({ userId: user.id, email: user.email, role: user.role });

    res.cookie('refresh_token', refreshToken, COOKIE_OPTIONS);

    res.status(201).json({
      message:     'Đăng ký thành công',
      accessToken,
      user: { id: user.id, name: user.name, email: user.email },
    });
  } catch (err) {
    res.status(500).json({ error: 'Lỗi server: ' + err.message });
  }
});

// ────────────────────────────────────────────
// POST /auth/login
// ────────────────────────────────────────────
router.post('/login', async (req, res) => {
  try {
    const { email, password } = req.body;

    if (!email || !password)
      return res.status(400).json({ error: 'Vui lòng nhập email và mật khẩu' });

    const user = userStore.findByEmail(email.toLowerCase());
    const fakeHash = '$2b$12$XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX';
    const isMatch = user
      ? await bcrypt.compare(password, user.passwordHash)
      : (await bcrypt.compare(password, fakeHash), false);

    if (!user || !isMatch)
      return res.status(401).json({ error: 'Email hoặc mật khẩu không đúng' });

    const accessToken  = signAccessToken({ userId: user.id, email: user.email, role: user.role });
    const refreshToken = signRefreshToken({ userId: user.id, email: user.email, role: user.role });

    res.cookie('refresh_token', refreshToken, COOKIE_OPTIONS);

    res.json({
      message:     'Đăng nhập thành công',
      accessToken,
      user: { id: user.id, name: user.name, email: user.email, role: user.role },
    });
  } catch (err) {
    res.status(500).json({ error: 'Lỗi server: ' + err.message });
  }
});

// ────────────────────────────────────────────
// POST /auth/refresh
// ────────────────────────────────────────────
router.post('/refresh', (req, res) => {
  const token = req.cookies.refresh_token;
  if (!token) return res.status(401).json({ error: 'Không có refresh token' });

  const decoded = verifyRefreshToken(token);
  if (!decoded) {
    res.clearCookie('refresh_token');
    return res.status(401).json({ error: 'Refresh token không hợp lệ hoặc đã hết hạn' });
  }

  // Kiểm tra user vẫn còn tồn tại
  const user = userStore.findById(decoded.userId);
  if (!user) {
    res.clearCookie('refresh_token');
    return res.status(401).json({ error: 'Tài khoản không tồn tại' });
  }

  const accessToken = signAccessToken({ userId: user.id, email: user.email, role: user.role });
  res.json({ accessToken });
});

// ────────────────────────────────────────────
// POST /auth/logout
// ────────────────────────────────────────────
router.post('/logout', (req, res) => {
  res.clearCookie('refresh_token', { httpOnly: true, secure: process.env.NODE_ENV === 'production' });
  res.json({ message: 'Đã đăng xuất thành công' });
});

// ────────────────────────────────────────────
// GET /auth/me — Thông tin user hiện tại (protected)
// ────────────────────────────────────────────
router.get('/me', authMiddleware, (req, res) => {
  const user = userStore.findById(req.user.userId);
  if (!user) return res.status(404).json({ error: 'Không tìm thấy user' });

  res.json({
    id:        user.id,
    name:      user.name,
    email:     user.email,
    role:      user.role,
    createdAt: user.createdAt,
  });
});

module.exports = router;

Tóm tắt chương 10
  • Cookie lưu dữ liệu nhỏ ở browser; dùng httpOnly + secure + sameSite để bảo mật
  • Session chỉ lưu ID ở browser, data ở server; MemoryStore chỉ dùng cho dev
  • bcrypt hash password với salt ngẫu nhiên và cost factor — không thể reverse; không dùng MD5/SHA
  • JWT là stateless token, payload có thể đọc được, signature bảo vệ tính toàn vẹn
  • Auth middleware đọc token từ header hoặc cookie, verify, đính kèm req.user
  • Refresh token dài hạn trong httpOnly cookie, access token ngắn hạn trong memory

Dễ

10.1 optionalAuth middleware

Thêm middleware optionalAuth vào dự án — không trả về lỗi 401 nếu chưa login, nhưng nếu có token hợp lệ thì đính kèm req.user. Dùng nó cho route GET /posts: nếu đã login thì hiện thêm trường isOwner: true cho những bài viết của user đó.

Trung bình

10.2 requireRole middleware factory

Implement requireRole(roles) nhận cả string lẫn array string. Test với 3 roles: 'user', 'moderator', 'admin'. Route DELETE /posts/:id chỉ cho phép moderator và admin. Route GET /admin/stats chỉ cho admin. Viết test case thủ công bằng curl.

Khó

10.3 JWT Blacklist khi đăng xuất

Implement token blacklist: khi user logout, thêm access token hiện tại vào một Set in-memory (hoặc Map kèm expiry). Trong authMiddleware, check token có trong blacklist không trước khi cho qua. Xử lý thêm: tự động dọn token đã hết hạn ra khỏi blacklist để tránh memory leak (dùng cron hoặc lazy cleanup).
