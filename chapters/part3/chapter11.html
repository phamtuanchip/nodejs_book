Chương 11: Templating Engine và Server-Side Rendering

Không phải mọi app đều cần React hay Vue. Server-side rendering đơn giản, SEO-friendly, và phù hợp cho nhiều loại web. Chương này xây dựng website blog thực sự với EJS — từ template đầu tiên đến hệ thống layout, form handling, và flash messages.

🎯 Sau chương này bạn sẽ hiểu được
  • SSR vs CSR vs SSG — khi nào dùng cái nào
  • Cài đặt và dùng EJS templating engine với Express
  • Tạo layout chung và partial templates (header, footer)
  • Handle form submission và POST-Redirect-GET pattern
  • Flash messages để thông báo kết quả cho user sau redirect
  • Xây dựng blog website đầy đủ với CRUD operations

11.1 SSR vs CSR vs SSG

Có ba cách chính để đưa nội dung từ server đến trình duyệt của người dùng. Hiểu sự khác biệt giúp bạn chọn đúng công cụ cho từng loại dự án.

Khi nào dùng cái nào?

Loại dự án Phương pháp phù hợp Lý do
Blog cá nhân, trang marketing SSG (Next.js, Hugo, Astro) Nội dung ít thay đổi, cần SEO, tốc độ tối đa
Website tin tức, thương mại điện tử SSR (Next.js, Express + EJS) Nội dung thay đổi theo giờ, cần SEO, dữ liệu động
Dashboard, ứng dụng quản lý CSR (React, Vue, Angular) UX phức tạp, dữ liệu real-time, không cần SEO
Trang docs, portfolio SSG Không cần server, deploy lên GitHub Pages miễn phí
Web app hybrid SSR + CSR (Next.js full) Trang marketing → SSR/SSG; trang app → CSR

11.2 EJS — Embedded JavaScript Templates

EJS (Embedded JavaScript) là templating engine phổ biến nhất cho Express. Nó cho phép nhúng code JavaScript trực tiếp vào HTML — học trong 30 phút, mạnh đủ dùng cho hầu hết dự án SSR thực tế. 

        

          Shell
          Terminal
          
        

        npm install ejs express
      
        

          JavaScript
          app.js — Thiết lập EJS với Express
          
        

        const express = require('express');
const path    = require('path');
const app     = express();

// Nói với Express dùng EJS làm view engine
app.set('view engine', 'ejs');

// Thư mục chứa các file template (mặc định là ./views)
app.set('views', path.join(__dirname, 'views'));

// Serve static files (CSS, JS, images)
app.use(express.static(path.join(__dirname, 'public')));

// Route đầu tiên
app.get('/', (req, res) => {
  // res.render('template-name', { biến truyền vào template })
  res.render('index', {
    title:   'Trang chủ',
    message: 'Chào mừng đến với EJS!',
    users: [
      { name: 'Alice', age: 28 },
      { name: 'Bob',   age: 32 },
      { name: 'Carol', age: 25 },
    ],
  });
});

app.listen(3000, () => console.log('Server tại http://localhost:3000'));

        <!DOCTYPE html>

<head>

  <!-- <%= %> output có escape HTML (an toàn, dùng với user input) -->
  <title><%= title %></title>
</head>
<body>

  <!-- <% %> thực thi code JS — if/else -->
  <% if (users.length === 0) { %>
    <p>Không có người dùng nào.</p>
  <% } else { %>
    <p>Có <%= users.length %> người dùng:</p>

    <!-- <% %> thực thi code JS — for loop -->
    <ul>
      <% users.forEach((user, index) => { %>
        <li>
          <!-- #{index+1} để đánh số 1-based -->
          <%= index + 1 %>. <strong><%= user.name %></strong> — <%= user.age %> tuổi
        </li>
      <% }) %>
    </ul>
  <% } %>

  <!-- <%- %> output KHÔNG escape — dùng khi bạn tin tưởng nội dung -->
  <!-- NGUY HIỂM nếu dùng với user input chưa sanitize -->
  <%- '<em>HTML thô này được render bình thường</em>' %>

  <!-- <%# %> comment — không xuất ra HTML -->
  <%# Dòng này sẽ không xuất hiện trong source HTML %>

</body>
</html>
Tag Tên gọi Dùng khi nào
<%= value %> Output (escaped) Xuất giá trị biến — tự động escape HTML (<, >, &) — an toàn với user input
<%- html %> Output (raw) Xuất HTML thô — chỉ dùng khi nội dung do bạn kiểm soát (không phải user input)
<% code %> Scriptlet Chạy code JS: if, for, khai báo biến, gọi function
<%# comment %> Comment Ghi chú trong template — không xuất ra HTML
<%- include(path) %> Include Nhúng file template khác vào — dùng cho partials
XSS và EJS escaping
Luôn dùng <%= %> (escaped) khi hiển thị dữ liệu từ user. Nếu dùng <%- %> với input từ người dùng, attacker có thể nhúng script độc hại vào trang — đây là lỗ hổng XSS (Cross-Site Scripting). Chỉ dùng <%- %> khi bạn tự tạo HTML (ví dụ: include partial template).

11.4 Form Handling và POST-Redirect-GET

HTML forms gửi dữ liệu đến server qua HTTP POST. Vấn đề kinh điển: nếu user nhấn F5 sau khi submit form, trình duyệt sẽ gửi lại request POST — tạo duplicate entry trong database. Pattern POST-Redirect-GET giải quyết điều này. 

        

          JavaScript
          routes/posts.js — Form handling với PRG pattern
          
        

        const express = require('express');
const router  = express.Router();

// Parse form data (application/x-www-form-urlencoded)
router.use(express.urlencoded({ extended: false }));

// In-memory post store
const posts = [];
let nextId = 1;

// ─── GET /posts — Danh sách bài viết ───
router.get('/', (req, res) => {
  // Sắp xếp mới nhất trước
  const sorted = [...posts].sort((a, b) => b.createdAt - a.createdAt);
  res.render('posts/index', { posts: sorted, title: 'Tất cả bài viết' });
});

// ─── GET /posts/new — Form tạo bài mới ───
// PHẢI đặt trước /posts/:id để tránh "new" bị parse thành id
router.get('/new', (req, res) => {
  res.render('posts/new', { title: 'Viết bài mới', errors: [], old: {} });
});

// ─── POST /posts — Xử lý submit form ───
router.post('/', (req, res) => {
  const { title, content, author } = req.body;
  const errors = [];

  // Server-side validation
  if (!title?.trim())   errors.push('Tiêu đề không được để trống');
  if (!content?.trim()) errors.push('Nội dung không được để trống');
  if (!author?.trim())  errors.push('Tên tác giả không được để trống');
  if (title?.length > 200) errors.push('Tiêu đề tối đa 200 ký tự');

  if (errors.length > 0) {
    // Render lại form với lỗi và dữ liệu cũ (không redirect)
    return res.status(422).render('posts/new', {
      title: 'Viết bài mới',
      errors,
      old: { title, content, author }, // giữ lại input của user
    });
  }

  const post = {
    id:        nextId++,
    title:     title.trim(),
    content:   content.trim(),
    author:    author.trim(),
    excerpt:   content.trim().slice(0, 150) + (content.length > 150 ? '...' : ''),
    createdAt: Date.now(),
    updatedAt: Date.now(),
  };
  posts.push(post);

  // POST-Redirect-GET: redirect sau khi lưu thành công
  res.redirect(`/posts/${post.id}`);
});

// ─── GET /posts/:id — Chi tiết bài viết ───
router.get('/:id', (req, res) => {
  const post = posts.find(p => p.id === parseInt(req.params.id));
  if (!post) return res.status(404).render('404', { title: 'Không tìm thấy' });

  res.render('posts/show', { post, title: post.title });
});

// ─── GET /posts/:id/edit — Form sửa bài ───
router.get('/:id/edit', (req, res) => {
  const post = posts.find(p => p.id === parseInt(req.params.id));
  if (!post) return res.status(404).render('404', { title: 'Không tìm thấy' });

  res.render('posts/edit', { post, title: `Sửa: ${post.title}`, errors: [] });
});

// ─── POST /posts/:id/update — Cập nhật bài (dùng POST thay PUT vì HTML form) ───
router.post('/:id/update', (req, res) => {
  const post = posts.find(p => p.id === parseInt(req.params.id));
  if (!post) return res.status(404).render('404', { title: 'Không tìm thấy' });

  const { title, content, author } = req.body;
  const errors = [];

  if (!title?.trim())   errors.push('Tiêu đề không được để trống');
  if (!content?.trim()) errors.push('Nội dung không được để trống');

  if (errors.length > 0) {
    return res.status(422).render('posts/edit', { post: { ...post, ...req.body }, title: `Sửa: ${post.title}`, errors });
  }

  post.title     = title.trim();
  post.content   = content.trim();
  post.author    = author?.trim() || post.author;
  post.excerpt   = content.trim().slice(0, 150) + '...';
  post.updatedAt = Date.now();

  res.redirect(`/posts/${post.id}`);
});

// ─── POST /posts/:id/delete — Xóa bài ───
router.post('/:id/delete', (req, res) => {
  const index = posts.findIndex(p => p.id === parseInt(req.params.id));
  if (index === -1) return res.status(404).render('404', { title: 'Không tìm thấy' });

  posts.splice(index, 1);
  res.redirect('/posts');
});

module.exports = { router, posts };

11.5 Flash Messages với connect-flash

Flash message là thông báo chỉ hiển thị một lần — sau khi đọc, nó biến mất. Hoàn hảo cho phản hồi sau form submission: "Đã lưu thành công!" hay "Đã xóa bài viết". Package connect-flash lưu flash message vào session, cho phép hiện sau redirect. 

        

          Shell
          Terminal
          
        

        npm install connect-flash express-session
      
        

          JavaScript
          app.js — Cấu hình connect-flash
          
        

        const session = require('express-session');
const flash   = require('connect-flash');

// Flash cần session để hoạt động
app.use(session({
  secret: 'blog-secret',
  resave: false,
  saveUninitialized: false,
}));

app.use(flash());

// Middleware để truyền flash messages vào TẤT CẢ templates
// (không cần truyền thủ công từng route)
app.use((req, res, next) => {
  res.locals.success = req.flash('success');
  res.locals.error   = req.flash('error');
  res.locals.warning = req.flash('warning');
  next();
});

// Sử dụng trong route:
router.post('/', (req, res) => {
  // ... tạo bài viết ...
  req.flash('success', 'Bài viết đã được đăng thành công!');
  res.redirect(`/posts/${post.id}`);
});

router.post('/:id/delete', (req, res) => {
  // ... xóa bài viết ...
  req.flash('success', 'Đã xóa bài viết');
  req.flash('warning', 'Hành động này không thể hoàn tác');
  res.redirect('/posts');
});

        const express = require('express');
const path    = require('path');
const session = require('express-session');
const flash   = require('connect-flash');
const { router: postsRouter } = require('./routes/posts');

const app = express();

// View engine
app.set('view engine', 'ejs');
app.set('views', path.join(__dirname, 'views'));

// Static files
app.use(express.static(path.join(__dirname, 'public')));

// Body parsing
app.use(express.urlencoded({ extended: false }));
app.use(express.json());

// Session + Flash
app.use(session({ secret: 'blog-dev-secret', resave: false, saveUninitialized: false }));
app.use(flash());

// Đưa flash messages vào locals (dùng được trong mọi template)
app.use((req, res, next) => {
  res.locals.success = req.flash('success');
  res.locals.error   = req.flash('error');
  res.locals.warning = req.flash('warning');
  next();
});

// Routes
app.get('/', (req, res) => res.redirect('/posts'));
app.use('/posts', postsRouter);

// 404 handler
app.use((req, res) => {
  res.status(404).render('404', { title: 'Trang không tồn tại' });
});

// Error handler
app.use((err, req, res, next) => {
  console.error(err);
  res.status(500).render('404', { title: 'Lỗi server: ' + err.message });
});

const PORT = process.env.PORT || 3000;
app.listen(PORT, () => {
  console.log(`Blog đang chạy tại http://localhost:${PORT}`);
});

method-override cho PUT và DELETE
HTML form chỉ hỗ trợ GET và POST. Để dùng PUT/PATCH/DELETE, cài npm install method-override và thêm ?_method=DELETE vào action URL. Trong chương này chúng ta dùng route /posts/:id/delete (POST) để đơn giản hơn. Cách dùng method-override sẽ được giới thiệu ở chương REST API.
Tóm tắt chương 11
  • SSR phù hợp cho nội dung động cần SEO; CSR cho app phức tạp; SSG cho nội dung tĩnh
  • EJS nhúng JS vào HTML: <%= %> (escaped), <%- %> (raw), <% %> (code), <%- include() %> (partial)
  • Partials giải quyết code lặp: header/footer dùng chung, include với biến truyền vào
  • POST-Redirect-GET tránh form resubmission khi refresh trang
  • Flash messages thông báo kết quả sau redirect, tự xóa sau khi đọc một lần
  • Luôn dùng <%= %> (escaped) với user input để tránh XSS
Bài tập thực hành
Dễ

11.1 Trang About

Thêm trang /about vào blog: tạo views/about.ejs, thêm route GET /about trong app.js, và thêm link "Về chúng tôi" vào navigation bar trong views/partials/header.ejs. Trang about hiển thị thông tin về blog và tác giả.

Trung bình

11.2 Phân trang (Pagination)

Implement phân trang trên trang chủ: 5 bài mỗi trang. Route GET /posts?page=2 hiển thị trang 2. Hiển thị nút Prev/Next và số trang hiện tại (Trang 2 / 4). Ẩn nút Prev ở trang 1, ẩn nút Next ở trang cuối. Truyền { posts, currentPage, totalPages, hasPrev, hasNext } vào template.

Khó

11.3 Tính năng tìm kiếm với keyword highlight

Implement GET /posts?q=keyword: lọc bài viết theo title và content. Trong template kết quả, highlight từ khóa trong tiêu đề bằng thẻ <mark> (dùng <%-> với string đã sanitize). Nếu không có kết quả, hiện thông báo "Không tìm thấy bài nào cho 'keyword'". Thêm form search vào navigation bar. Kết hợp với phân trang từ bài 11.2.
