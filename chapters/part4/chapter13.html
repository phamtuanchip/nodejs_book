Chương 13: SQL với PostgreSQL và Prisma ORM

Khi data có quan hệ chặt chẽ và cần ACID transactions, SQL là lựa chọn tốt nhất. Prisma biến SQL thành code JavaScript/TypeScript type-safe, dễ đọc như viết object — không cần biết SQL phức tạp mà vẫn làm được mọi thứ.

🎯 Sau chương này bạn sẽ
  • Hiểu SQL cơ bản: SELECT, INSERT, UPDATE, DELETE, JOIN
  • Setup PostgreSQL miễn phí trên Supabase
  • Viết Prisma schema, chạy migration, generate client
  • Định nghĩa relations: one-to-many và many-to-many
  • CRUD với Prisma Client (find, create, update, delete)
  • Nested queries và include (tương đương JOIN)
  • Transactions để đảm bảo tính toàn vẹn dữ liệu
  • Aggregation và groupBy

13.1 SQL Fundamentals — Những Gì Cần Biết

SQL (Structured Query Language) là ngôn ngữ tiêu chuẩn để làm việc với relational database. Bạn không cần thành thạo SQL khi dùng Prisma, nhưng hiểu cơ bản giúp bạn debug và tối ưu hiệu quả hơn.

SELECT — Đọc dữ liệu

SQLQueries cơ bản
-- Lấy tất cả users
SELECT * FROM users;

-- Lấy fields cụ thể
SELECT id, name, email, created_at FROM users;

-- WHERE — filter
SELECT * FROM users
WHERE role = 'admin' AND is_active = true;

-- ORDER BY, LIMIT, OFFSET — sort và pagination
SELECT * FROM users
WHERE role = 'user'
ORDER BY created_at DESC
LIMIT 10 OFFSET 20;  -- Page 3 (skip 20 = 2 pages × 10)

-- LIKE — tìm kiếm text
SELECT * FROM users
WHERE name ILIKE '%nguyen%';  -- ILIKE: case-insensitive (PostgreSQL)

-- COUNT — đếm
SELECT COUNT(*) as total FROM users WHERE is_active = true;

-- Aggregate functions
SELECT
  role,
  COUNT(*) as count,
  MAX(created_at) as latest
FROM users
GROUP BY role
ORDER BY count DESC;

JOIN — Kết hợp nhiều bảng

SQLJOIN examples
-- INNER JOIN — chỉ lấy rows có match cả 2 bảng
SELECT
  posts.id,
  posts.title,
  posts.view_count,
  users.name AS author_name,
  users.email AS author_email
FROM posts
INNER JOIN users ON posts.author_id = users.id
WHERE posts.is_published = true
ORDER BY posts.created_at DESC
LIMIT 20;

-- LEFT JOIN — lấy tất cả posts, kể cả không có author
SELECT
  posts.title,
  COALESCE(users.name, 'Ẩn danh') AS author_name
FROM posts
LEFT JOIN users ON posts.author_id = users.id;

-- JOIN nhiều bảng
SELECT
  orders.id AS order_id,
  users.name AS customer,
  products.name AS product,
  order_items.quantity,
  order_items.price
FROM order_items
INNER JOIN orders ON order_items.order_id = orders.id
INNER JOIN users ON orders.user_id = users.id
INNER JOIN products ON order_items.product_id = products.id
WHERE orders.status = 'DELIVERED';

INSERT, UPDATE, DELETE

SQLMutations
-- INSERT — dùng $1, $2 để tránh SQL injection (parameterized query)
INSERT INTO posts (title, content, author_id, is_published)
VALUES ($1, $2, $3, $4)
RETURNING *;  -- PostgreSQL: trả về row vừa insert

-- UPDATE
UPDATE users
SET last_login = NOW(), updated_at = NOW()
WHERE id = $1
RETURNING id, name, last_login;

-- DELETE
DELETE FROM comments
WHERE post_id = $1 AND created_at < $2
RETURNING id;
💡 Dùng pg package (raw SQL)

Trước Prisma, người ta dùng pg package để query raw SQL. Prisma được xây trên nền đó và tự động generate SQL tối ưu cho bạn. Hiểu SQL raw giúp bạn debug khi Prisma generate query không như mong muốn.

13.3 Prisma Schema — Định Nghĩa Cấu Trúc Database

File prisma/schema.prisma là nguồn sự thật duy nhất cho toàn bộ cấu trúc database. Từ đây, Prisma sẽ generate SQL migration và TypeScript client.

Schema đầy đủ cho hệ thống e-commerce

Prismaprisma/schema.prisma
// prisma/schema.prisma
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider  = "postgresql"
  url       = env("DATABASE_URL")
  directUrl = env("DIRECT_URL")  // Cần cho Supabase connection pooler
}

// ─── Models ────────────────────────────────────────────────

model User {
  id        Int      @id @default(autoincrement())
  email     String   @unique
  name      String
  password  String
  role      Role     @default(USER)
  avatar    String?  // ? = nullable (optional)
  bio       String?  @db.VarChar(200)
  orders    Order[]  // Relation: 1 user có nhiều orders
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt  // Tự update khi record thay đổi

  @@index([email])  // Index cho email (ngoài unique)
  @@map("users")    // Tên bảng thực trong DB là "users" (không phải "User")
}

model Category {
  id       Int       @id @default(autoincrement())
  name     String    @unique
  slug     String    @unique
  products Product[] @relation("ProductCategories") // Many-to-many

  @@map("categories")
}

model Product {
  id          Int         @id @default(autoincrement())
  name        String
  description String?
  price       Decimal     @db.Decimal(10, 2) // Chính xác cho tiền tệ
  stock       Int         @default(0)
  imageUrl    String?
  isActive    Boolean     @default(true)
  categories  Category[]  @relation("ProductCategories") // Many-to-many
  orderItems  OrderItem[]
  createdAt   DateTime    @default(now())
  updatedAt   DateTime    @updatedAt

  @@index([isActive, price])
  @@map("products")
}

model Order {
  id         Int         @id @default(autoincrement())
  user       User        @relation(fields: [userId], references: [id])
  userId     Int
  status     OrderStatus @default(PENDING)
  total      Decimal     @db.Decimal(10, 2)
  address    Json        // Lưu địa chỉ dạng JSON object
  items      OrderItem[]
  note       String?
  createdAt  DateTime    @default(now())
  updatedAt  DateTime    @updatedAt

  @@index([userId, status])
  @@map("orders")
}

model OrderItem {
  id        Int     @id @default(autoincrement())
  order     Order   @relation(fields: [orderId], references: [id], onDelete: Cascade)
  orderId   Int
  product   Product @relation(fields: [productId], references: [id])
  productId Int
  quantity  Int
  price     Decimal @db.Decimal(10, 2) // Lưu giá tại thời điểm mua

  @@unique([orderId, productId]) // Mỗi product chỉ 1 lần trong 1 order
  @@map("order_items")
}

// ─── Enums ────────────────────────────────────────────────
enum Role {
  USER
  MODERATOR
  ADMIN
}

enum OrderStatus {
  PENDING      // Chờ xác nhận
  CONFIRMED    // Đã xác nhận
  SHIPPING     // Đang giao
  DELIVERED    // Đã giao
  CANCELLED    // Đã hủy
}

Seed script

JavaScriptprisma/seed.js
// prisma/seed.js
const { PrismaClient } = require('@prisma/client');
const bcrypt = require('bcrypt');

const prisma = new PrismaClient();

async function main() {
  // Tạo categories
  const categories = await Promise.all([
    prisma.category.upsert({
      where: { slug: 'electronics' },
      update: {},
      create: { name: 'Điện tử', slug: 'electronics' },
    }),
    prisma.category.upsert({
      where: { slug: 'clothing' },
      update: {},
      create: { name: 'Thời trang', slug: 'clothing' },
    }),
  ]);

  // Tạo admin user
  const hashedPass = await bcrypt.hash('Admin@123', 12);
  const admin = await prisma.user.upsert({
    where: { email: 'admin@example.com' },
    update: {},
    create: {
      email: 'admin@example.com',
      name: 'Admin',
      password: hashedPass,
      role: 'ADMIN',
    },
  });

  console.log(`✅ Seeded: ${categories.length} categories, admin user`);
}

main()
  .catch(console.error)
  .finally(() => prisma.$disconnect());

// ── Pagination helper ──
async function getProducts({ page = 1, limit = 12, categorySlug }) {
  const skip = (page - 1) * limit;
  const where = {
    isActive: true,
    ...(categorySlug && {
      categories: { some: { slug: categorySlug } },
    }),
  };

  const [products, total] = await prisma.$transaction([
    prisma.product.findMany({
      where,
      include: { categories: { select: { name: true, slug: true } } },
      orderBy: { createdAt: 'desc' },
      take: limit,
      skip,
    }),
    prisma.product.count({ where }),
  ]);

  return {
    data: products,
    pagination: { page, limit, total, totalPages: Math.ceil(total / limit) },
  };
}

13.7 Transactions — Đảm Bảo Tính Toàn Vẹn

Transaction đảm bảo rằng một nhóm operations hoặc tất cả thành công hoặc tất cả thất bại — không bao giờ có trạng thái nửa vời. Ví dụ: tạo order và trừ stock phải xảy ra đồng thời. 

JavaScriptTạo order trong transaction
const prisma = require('./lib/prisma');

async function checkout(userId, cartItems, shippingAddress) {
  // cartItems = [{ productId: 1, quantity: 2 }, { productId: 3, quantity: 1 }]

  return await prisma.$transaction(async (tx) => {
    // 'tx' là Prisma Client nhưng trong context transaction
    // Mọi operation dùng 'tx' đều trong cùng 1 transaction

    // ── Bước 1: Kiểm tra và lấy thông tin sản phẩm ──
    const productIds = cartItems.map(item => item.productId);
    const products = await tx.product.findMany({
      where: { id: { in: productIds }, isActive: true },
    });

    if (products.length !== productIds.length) {
      throw new Error('Một số sản phẩm không tồn tại hoặc đã bị xóa');
    }

    // ── Bước 2: Kiểm tra tồn kho và tính tổng tiền ──
    const orderItemsData = [];
    let total = 0;

    for (const cartItem of cartItems) {
      const product = products.find(p => p.id === cartItem.productId);

      if (product.stock < cartItem.quantity) {
        throw new Error(`Sản phẩm "${product.name}" chỉ còn ${product.stock} trong kho`);
      }

      const itemTotal = Number(product.price) * cartItem.quantity;
      total += itemTotal;

      orderItemsData.push({
        productId: product.id,
        quantity: cartItem.quantity,
        price: product.price,  // Lưu giá tại thời điểm mua
      });
    }

    // ── Bước 3: Tạo order với items ──
    const order = await tx.order.create({
      data: {
        userId,
        total,
        status: 'CONFIRMED',
        address: shippingAddress,
        items: { create: orderItemsData },
      },
      include: {
        items: {
          include: { product: { select: { name: true } } },
        },
      },
    });

    // ── Bước 4: Trừ tồn kho (atomic) ──
    await Promise.all(
      cartItems.map(item =>
        tx.product.update({
          where: { id: item.productId },
          data: { stock: { decrement: item.quantity } },
        })
      )
    );

    // Nếu bất kỳ step nào throw error, toàn bộ sẽ tự động ROLLBACK
    return order;
  }, {
    maxWait: 5000,   // Thời gian chờ lấy connection từ pool (ms)
    timeout: 10000,  // Timeout của toàn bộ transaction (ms)
  });
}

// Sử dụng
app.post('/api/checkout', async (req, res) => {
  try {
    const order = await checkout(req.user.id, req.body.items, req.body.address);
    res.json({ success: true, order });
  } catch (error) {
    // Nếu là lỗi business (hết hàng), trả 400
    if (error.message.includes('kho')) {
      return res.status(400).json({ error: error.message });
    }
    res.status(500).json({ error: 'Lỗi hệ thống' });
  }
});

13.8 Aggregation — Thống Kê Nâng Cao

JavaScriptAggregation và groupBy
// ── aggregate — tính toán trên tập dữ liệu ──
const orderStats = await prisma.order.aggregate({
  where: {
    status: 'DELIVERED',
    createdAt: { gte: new Date('2024-01-01') },
  },
  _count: { id: true },
  _sum: { total: true },
  _avg: { total: true },
  _min: { total: true },
  _max: { total: true },
});

console.log(`Tổng orders: ${orderStats._count.id}`);
console.log(`Doanh thu: ${orderStats._sum.total}`);
console.log(`Trung bình: ${orderStats._avg.total}`);

// ── groupBy — nhóm theo field ──
const revenueByMonth = await prisma.order.groupBy({
  by: ['status'],
  where: {
    createdAt: {
      gte: new Date('2024-01-01'),
      lt: new Date('2025-01-01'),
    },
  },
  _count: { id: true },
  _sum: { total: true },
  orderBy: { _sum: { total: 'desc' } },
});

// User stats — dùng raw SQL cho query phức tạp
const topCustomers = await prisma.$queryRaw`
  SELECT
    u.id,
    u.name,
    u.email,
    COUNT(o.id)::int AS order_count,
    SUM(o.total)::float AS total_spent
  FROM users u
  INNER JOIN orders o ON o.user_id = u.id
  WHERE o.status = 'DELIVERED'
  GROUP BY u.id, u.name, u.email
  ORDER BY total_spent DESC
  LIMIT 10
`;
📋 Tóm tắt Chương 13
  • PostgreSQL: relational DB mạnh nhất open-source, phù hợp khi cần ACID và quan hệ phức tạp
  • Prisma schema: nguồn sự thật duy nhất — định nghĩa models, relations, enums
  • Migration: npx prisma migrate dev tạo SQL và apply vào DB
  • Prisma Client: API type-safe với findMany, findUnique, create, update, delete, upsert
  • Relations: include để join, select để chọn fields, _count để đếm related records
  • Transactions: prisma.$transaction(async tx => {}) cho nhóm operations atomic
  • Aggregation: aggregate, groupBy, $queryRaw cho thống kê phức tạp
  • Dùng $queryRaw khi cần SQL thuần — không bao giờ interpolate user input trực tiếp

Dễ

Bài 1: Thêm Category và Many-to-Many

Đã có model Category và Product với quan hệ many-to-many trong schema. Viết: (1) Route GET /categories lấy tất cả categories kèm số lượng products; (2) Route GET /categories/:slug/products lấy danh sách products theo category với pagination; (3) Route POST /products/:id/categories gán categories cho product (nhận array categoryIds, dùng set thay vì connect).

Trung bình

Bài 2: User Dashboard Stats

Viết route GET /users/:id/stats trả về object: totalOrders (int), totalSpent (số tiền), favoriteCategory (category mà user mua nhiều nhất theo quantity), ordersByStatus (object đếm orders theo từng status). Dùng combination của Prisma aggregate, groupBy và raw SQL nếu cần. Handle case user chưa có order nào.

Khó

Bài 3: Cart và Checkout hoàn chỉnh

Thêm model Cart và CartItem vào schema. Implement: (1) POST /cart/items — thêm vào giỏ hàng (nếu đã có thì tăng quantity); (2) DELETE /cart/items/:productId — xóa khỏi giỏ; (3) GET /cart — xem giỏ hàng với product info và tổng tiền; (4) POST /cart/checkout — tạo order từ cart, trừ stock, clear cart, tất cả trong 1 transaction. Xử lý đầy đủ: sản phẩm hết hàng, sản phẩm bị xóa, giỏ hàng rỗng.
