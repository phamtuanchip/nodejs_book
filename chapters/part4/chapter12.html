Chương 12: MongoDB với Mongoose — Database NoSQL

MongoDB lưu data như JSON object — không cần schema cứng nhắc, scale dễ dàng. Mongoose thêm validation, hooks, và relationships trên nền MongoDB, biến việc làm việc với database thành trải nghiệm tự nhiên và an toàn.

🎯 Sau chương này bạn sẽ
  • Hiểu sự khác biệt NoSQL vs SQL và khi nào chọn MongoDB
  • Kết nối NodeJS với MongoDB Atlas (cloud miễn phí)
  • Định nghĩa Schema và Model với Mongoose
  • Thực hiện CRUD đầy đủ: Create, Read, Update, Delete
  • Dùng Population để liên kết các document
  • Viết Middleware hooks (pre/post) để tự động hóa logic
  • Aggregation pipeline cho thống kê phức tạp
  • Tạo Indexes để tăng tốc truy vấn

12.1 NoSQL vs SQL — Chọn Gì Cho Đúng?

Trước khi học MongoDB, cần hiểu rõ tại sao bạn chọn nó thay vì SQL. Đây không phải là "cái nào tốt hơn" — mà là "cái nào phù hợp hơn cho bài toán này".

Tiêu chí SQL (MySQL, PostgreSQL) MongoDB (NoSQL)
Cấu trúc dữ liệu Bảng với hàng và cột cố định Collection chứa Documents (JSON)
Schema Cứng nhắc — phải định nghĩa trước Linh hoạt — có thể thay đổi
Quan hệ JOIN giữa các bảng Embed hoặc Reference + populate
ACID Đầy đủ natively Hỗ trợ từ v4.0 (multi-doc transactions)
Scale Vertical (nâng cấp server) Horizontal (sharding)
Khi nào dùng Tài chính, quan hệ phức tạp, báo cáo Social, catalog, content, real-time

MongoDB phù hợp khi nào?

  • Social media — Mỗi user profile có fields khác nhau (bio, links, preferences)
  • Product catalog — Sản phẩm có attributes rất khác nhau (điện thoại vs áo quần)
  • Content management — Blog, CMS, nơi mỗi loại content có cấu trúc riêng
  • Real-time analytics — Ghi log nhanh, không cần schema chặt
  • IoT data — Cảm biến gửi dữ liệu với format biến đổi

12.2 MongoDB Atlas — Setup Cloud Miễn Phí

MongoDB Atlas là dịch vụ cloud chính thức của MongoDB. Tier M0 miễn phí hoàn toàn — đủ dùng cho học tập và project nhỏ.

Bước 1: Tạo tài khoản và cluster

  1. Vào cloud.mongodb.com → Sign up miễn phí
  2. Chọn Create a deployment → M0 Free
  3. Chọn provider (AWS/GCP/Azure) và region gần nhất (Singapore)
  4. Đặt tên cluster và tạo
  5. Tạo Database User: username + password mạnh
  6. Network Access → Add IP Address → 0.0.0.0/0 (cho phép mọi IP trong development)

Bước 3: Cài Mongoose và kết nối

ShellTerminal
npm install mongoose dotenv
JavaScriptconfig/database.js
// config/database.js
const mongoose = require('mongoose');

const MONGODB_URI = process.env.MONGODB_URI;
const MAX_RETRIES = 5;
let retryCount = 0;

async function connectDB() {
  try {
    await mongoose.connect(MONGODB_URI, {
      // Mongoose 6+ không cần useNewUrlParser, useUnifiedTopology nữa
      serverSelectionTimeoutMS: 5000,  // Timeout sau 5s nếu không kết nối được
      heartbeatFrequencyMS: 10000,     // Kiểm tra kết nối mỗi 10s
    });

    console.log('✅ MongoDB kết nối thành công');
    retryCount = 0; // Reset counter khi thành công

  } catch (error) {
    console.error(`❌ MongoDB lỗi (lần ${retryCount + 1}/${MAX_RETRIES}):`, error.message);

    if (retryCount < MAX_RETRIES) {
      retryCount++;
      const delay = Math.min(1000 * 2 ** retryCount, 30000); // Exponential backoff, max 30s
      console.log(`Thử lại sau ${delay / 1000}s...`);
      setTimeout(connectDB, delay);
    } else {
      console.error('Đã thử quá nhiều lần. Thoát...');
      process.exit(1);
    }
  }
}

// Lắng nghe các events của Mongoose
mongoose.connection.on('connected', () => {
  console.log('📗 Mongoose connected to MongoDB');
});

mongoose.connection.on('error', (err) => {
  console.error('📕 Mongoose connection error:', err);
});

mongoose.connection.on('disconnected', () => {
  console.log('📙 Mongoose disconnected — Đang thử kết nối lại...');
  connectDB();
});

// Đóng kết nối khi app tắt
process.on('SIGINT', async () => {
  await mongoose.connection.close();
  console.log('MongoDB kết nối đã đóng (app shutdown)');
  process.exit(0);
});

module.exports = { connectDB };
JavaScriptapp.js

const express = require('express');

// Kết nối DB trước khi start server

12.3 Schema và Model — Blueprint của Document

Mongoose thêm lớp Schema lên MongoDB để định nghĩa cấu trúc, kiểu dữ liệu và validation. Dù MongoDB linh hoạt, trong thực tế bạn vẫn cần đảm bảo data nhất quán — đó là việc của Schema.

Các kiểu dữ liệu trong Mongoose

Type Ví dụ Ghi chú
String name: String Text, có thể dùng trim, lowercase, uppercase
Number age: Number Integer hoặc float, có min/max
Boolean isActive: Boolean true/false
Date birthday: Date Lưu dạng ISO, so sánh được
mongoose.Schema.Types.ObjectId author: ObjectId Reference đến document khác
[String] tags: [String] Mảng các giá trị
Mixed metadata: Mixed Bất kỳ kiểu gì (dùng cẩn thận)

Schema đầy đủ cho hệ thống user

JavaScriptmodels/User.js
const mongoose = require('mongoose');
const bcrypt = require('bcrypt');

const userSchema = new mongoose.Schema({
  // String với validation
  name: {
    type: String,
    required: [true, 'Tên không được để trống'],
    trim: true,              // Tự cắt khoảng trắng 2 đầu
    minlength: [2, 'Tên phải từ 2 ký tự'],
    maxlength: [50, 'Tên không quá 50 ký tự'],
  },

  email: {
    type: String,
    required: [true, 'Email không được để trống'],
    unique: true,            // Tạo unique index
    lowercase: true,         // Tự chuyển thành chữ thường
    trim: true,
    match: [/^\S+@\S+\.\S+$/, 'Email không hợp lệ'],
  },

  password: {
    type: String,
    required: true,
    minlength: [6, 'Mật khẩu tối thiểu 6 ký tự'],
    select: false,           // Mặc định KHÔNG trả về trong query (bảo mật!)
  },

  role: {
    type: String,
    enum: {
      values: ['user', 'moderator', 'admin'],
      message: 'Role không hợp lệ: {VALUE}',
    },
    default: 'user',
  },

  avatar: {
    type: String,
    default: null,
  },

  bio: {
    type: String,
    maxlength: 200,
    default: '',
  },

  // Reference đến document khác
  followers: [{
    type: mongoose.Schema.Types.ObjectId,
    ref: 'User',  // Tên model để populate
  }],

  isActive: {
    type: Boolean,
    default: true,
  },

  lastLogin: {
    type: Date,
    default: null,
  },

}, {
  timestamps: true,         // Tự thêm createdAt và updatedAt
  toJSON: { virtuals: true },  // Include virtual fields khi convert sang JSON
  toObject: { virtuals: true },
});

// ── Virtual field (không lưu DB, tính khi cần) ──
userSchema.virtual('followerCount').get(function () {
  return this.followers ? this.followers.length : 0;
});

// ── Instance method ──
userSchema.methods.comparePassword = async function (candidatePassword) {
  return bcrypt.compare(candidatePassword, this.password);
};

// ── Static method ──
userSchema.statics.findByEmail = function (email) {
  return this.findOne({ email: email.toLowerCase() });
};

const User = mongoose.model('User', userSchema);

module.exports = User;
💡 select: false — Quan trọng cho bảo mật

Đặt select: false cho field password nghĩa là mọi query mặc định sẽ không trả về password. Khi cần (đăng nhập), dùng .select('+password') để lấy về.

JavaScriptQuery dữ liệu
// Tìm tất cả (có filter)
const admins = await User.find({ role: 'admin', isActive: true });

// ── Query operators ──
const users = await User.find({
  role: { $in: ['admin', 'moderator'] },   // role là admin hoặc moderator
  createdAt: { $gte: new Date('2024-01-01') }, // tạo từ đầu 2024
  name: { $regex: /nguyen/i },              // tên chứa "nguyen" (case-insensitive)
});

// ── Chaining methods ──
const result = await User
  .find({ isActive: true })
  .select('name email avatar role')   // Chỉ lấy các fields này
  .sort({ createdAt: -1 })           // Mới nhất trước (-1) hoặc cũ nhất (1)
  .limit(10)                         // Tối đa 10 kết quả
  .skip(20)                          // Bỏ qua 20 đầu (cho pagination)
  .lean();                           // Trả về plain JS object (nhanh hơn Mongoose document)

// ── Pagination helper ──
async function getUsers({ page = 1, limit = 10, search = '' }) {
  const skip = (page - 1) * limit;
  const filter = search
    ? { $or: [
        { name: { $regex: search, $options: 'i' } },
        { email: { $regex: search, $options: 'i' } },
      ]}
    : {};

  const [users, total] = await Promise.all([
    User.find(filter).select('-password').sort({ createdAt: -1 }).skip(skip).limit(limit).lean(),
    User.countDocuments(filter),
  ]);

  return {
    data: users,
    pagination: {
      page,
      limit,
      total,
      totalPages: Math.ceil(total / limit),
      hasNext: page * limit < total,
      hasPrev: page > 1,
    },
  };
}

12.5 Population — Liên Kết Documents

MongoDB không có JOIN như SQL, nhưng Mongoose có populate — tự động thay thế ObjectId bằng document thực tế từ collection khác. 

JavaScriptmodels/Post.js
const mongoose = require('mongoose');

const commentSchema = new mongoose.Schema({
  author: {
    type: mongoose.Schema.Types.ObjectId,
    ref: 'User',
    required: true,
  },
  content: { type: String, required: true },
  likes: [{ type: mongoose.Schema.Types.ObjectId, ref: 'User' }],
  createdAt: { type: Date, default: Date.now },
});

const postSchema = new mongoose.Schema({
  title: { type: String, required: true, trim: true },
  content: { type: String, required: true },
  author: {
    type: mongoose.Schema.Types.ObjectId,
    ref: 'User',   // Tên model để populate
    required: true,
  },
  tags: [String],
  comments: [commentSchema],  // Embed sub-documents
  viewCount: { type: Number, default: 0 },
  isPublished: { type: Boolean, default: false },
}, { timestamps: true });

module.exports = mongoose.model('Post', postSchema);
JavaScriptSử dụng populate
const Post = require('./models/Post');

// Populate đơn giản
const post = await Post.findById(postId)
  .populate('author', 'name email avatar');  // Chỉ lấy name, email, avatar từ User

// Populate nhiều fields
const posts = await Post.find({ isPublished: true })
  .populate('author', 'name avatar')
  .populate('comments.author', 'name avatar')
  .sort({ createdAt: -1 });

// Populate với filter
const post2 = await Post.findById(postId)
  .populate({
    path: 'author',
    select: 'name email',
    match: { isActive: true },   // Chỉ populate nếu user đang active
  });

// Lấy posts với thông tin author + số lượng comments
const postsWithStats = await Post.find({ isPublished: true })
  .populate('author', 'name avatar')
  .lean()
  .then(posts => posts.map(p => ({
    ...p,
    commentCount: p.comments.length,
  })));
📌 Embed vs Reference

Embed (nhúng vào document — như comments trong post): khi data thường được đọc cùng nhau, không bao giờ đọc riêng, array không quá lớn (<100 items). Reference (ObjectId + populate — như author của post): khi data được dùng độc lập, cần update riêng, hoặc array có thể rất lớn.

12.6 Middleware (Hooks) — Tự Động Hóa Logic

Mongoose Middleware (còn gọi là hooks) cho phép thực thi code trước hoặc sau một operation nhất định. Dùng để hash password, ghi log, xóa data liên quan, v.v. 

JavaScriptmodels/User.js — với middleware
const mongoose = require('mongoose');
const bcrypt = require('bcrypt');

const userSchema = new mongoose.Schema({ /* ...fields như trên... */ });

// ── PRE SAVE HOOK — Hash password trước khi lưu ──
userSchema.pre('save', async function (next) {
  // 'this' là document đang được save
  // Chỉ hash khi password thực sự thay đổi
  if (!this.isModified('password')) return next();

  try {
    const saltRounds = 12;
    this.password = await bcrypt.hash(this.password, saltRounds);
    next();
  } catch (error) {
    next(error); // Truyền lỗi về Mongoose
  }
});

// ── PRE FIND HOOK — Tự filter users bị xóa mềm ──
userSchema.pre(/^find/, function (next) {
  // 'this' là query object
  // Tự động filter isDeleted nếu không có trong query
  if (this._conditions.isDeleted === undefined) {
    this.where({ isDeleted: { $ne: true } });
  }
  next();
});

// ── POST SAVE HOOK — Ghi log sau khi tạo user mới ──
userSchema.post('save', function (doc, next) {
  if (doc.wasNew) {  // Chỉ log khi là document mới
    console.log(`📧 User mới tạo: ${doc.email} lúc ${doc.createdAt}`);
    // Có thể gửi email welcome ở đây
  }
  next();
});

// ── POST DELETE HOOK — Cleanup data liên quan ──
userSchema.post('findOneAndDelete', async function (doc) {
  if (!doc) return;
  // Xóa tất cả posts của user này
  await mongoose.model('Post').deleteMany({ author: doc._id });
  console.log(`🗑️ Đã xóa posts của user: ${doc.email}`);
});

12.7 Aggregation Pipeline — Phân Tích Dữ Liệu

Aggregation pipeline cho phép xử lý và biến đổi data trực tiếp trong MongoDB, rất mạnh cho báo cáo và thống kê. Dữ liệu đi qua các stages theo thứ tự. 

JavaScriptAggregation examples
const Post = require('./models/Post');

// ── Thống kê bài viết theo tháng ──
const monthlyStats = await Post.aggregate([
  // Stage 1: Chỉ lấy bài đã publish trong năm 2024
  { $match: {
    isPublished: true,
    createdAt: { $gte: new Date('2024-01-01'), $lt: new Date('2025-01-01') }
  }},

  // Stage 2: Group theo năm-tháng
  { $group: {
    _id: {
      year: { $year: '$createdAt' },
      month: { $month: '$createdAt' },
    },
    count: { $sum: 1 },
    totalViews: { $sum: '$viewCount' },
    avgViews: { $avg: '$viewCount' },
  }},

  // Stage 3: Sort từ mới nhất
  { $sort: { '_id.year': -1, '_id.month': -1 } },

  // Stage 4: Format lại output
  { $project: {
    _id: 0,
    period: { $concat: [
      { $toString: '$_id.year' }, '-',
      { $cond: [{ $lt: ['$_id.month', 10] }, '0', ''] },
      { $toString: '$_id.month' },
    ]},
    count: 1,
    totalViews: 1,
    avgViews: { $round: ['$avgViews', 0] },
  }},
]);

// ── Top 5 tags phổ biến nhất ──
const topTags = await Post.aggregate([
  { $match: { isPublished: true } },
  { $unwind: '$tags' },  // Tách mỗi tag thành 1 document riêng
  { $group: { _id: '$tags', count: { $sum: 1 } }},
  { $sort: { count: -1 } },
  { $limit: 5 },
  { $project: { _id: 0, tag: '$_id', count: 1 } },
]);

// ── $lookup — JOIN giữa 2 collections ──
const postsWithAuthorDetails = await Post.aggregate([
  { $match: { isPublished: true } },
  {
    $lookup: {
      from: 'users',          // Tên collection (lowercase, plural)
      localField: 'author',   // Field trong Post
      foreignField: '_id',    // Field trong User
      as: 'authorInfo',       // Tên field kết quả
    }
  },
  { $unwind: '$authorInfo' },
  { $project: {
    title: 1, viewCount: 1, createdAt: 1,
    'author.name': '$authorInfo.name',
    'author.avatar': '$authorInfo.avatar',
  }},
  { $limit: 10 },
]);

12.8 Indexes — Tăng Tốc Truy Vấn

Không có index, MongoDB phải quét toàn bộ collection mỗi query. Index như mục lục sách — giúp tìm nhanh mà không cần đọc từng trang. 

JavaScriptTạo indexes
const postSchema = new mongoose.Schema({ /* ... */ });

// Index đơn
postSchema.index({ createdAt: -1 });           // Sort theo thời gian tạo
postSchema.index({ isPublished: 1 });           // Filter theo trạng thái

// Compound index — phù hợp với query có nhiều điều kiện
postSchema.index({ isPublished: 1, createdAt: -1 });  // Lọc published rồi sort

// Text index — cho full-text search
postSchema.index({ title: 'text', content: 'text' }, {
  weights: { title: 10, content: 1 },  // title quan trọng hơn content (10x)
  name: 'post_search_index',
});

// Unique index
postSchema.index({ slug: 1 }, { unique: true });

// Sparse index — chỉ index documents có field này
postSchema.index({ githubId: 1 }, { sparse: true });

// TTL index — tự xóa document sau một thời gian
const sessionSchema = new mongoose.Schema({
  token: String,
  createdAt: { type: Date, expires: '7d' },  // Tự xóa sau 7 ngày
});
JavaScriptFull-text search
// Search với text index (phải có text index trước)
const results = await Post.find({
  $text: { $search: 'nodejs async programming' },
  isPublished: true,
}, {
  score: { $meta: 'textScore' },  // Thêm relevance score
})
.sort({ score: { $meta: 'textScore' } })  // Sort theo relevance
.limit(10)
.lean();

// Kiểm tra query plan (explain)
const plan = await Post.find({ isPublished: true })
  .sort({ createdAt: -1 })
  .explain('executionStats');

console.log('Index used:', plan.queryPlanner.winningPlan.inputStage.indexName);
console.log('Docs scanned:', plan.executionStats.totalDocsExamined);
console.log('Docs returned:', plan.executionStats.nReturned);
⚠️ Index không phải lúc nào cũng tốt

Mỗi index chiếm dung lượng RAM và làm chậm Write operations (vì phải cập nhật index). Chỉ tạo index cho các fields thực sự hay được dùng trong query. Dùng explain() để kiểm tra query có dùng index không.
