Chương 7: npm Ecosystem — Quản Lý Packages và Dependencies

npm là kho thư viện lớn nhất thế giới với hơn 2 triệu packages và hàng tỷ lượt tải mỗi tuần. Hiểu rõ npm giúp bạn quản lý project chuyên nghiệp, tránh các pitfalls phổ biến về phiên bản, bảo mật và hiệu suất.

🎯 Sau chương này bạn sẽ
  • Hiểu npm là gì và sự khác biệt giữa npm, yarn, pnpm
  • Đọc và viết package.json đúng chuẩn với từng field
  • Phân biệt dependencies, devDependencies, peerDependencies
  • Hiểu Semantic Versioning và các range operators (^, ~, *)
  • Viết npm scripts hiệu quả với pre/post hooks
  • Tạo và publish npm package của riêng mình
  • Dùng npm audit để kiểm tra bảo mật
  • Hiểu sự khác biệt giữa npm install và npm ci

7.1 npm là gì?

npm (Node Package Manager) thực ra là 3 thứ riêng biệt:

  • CLI tool — lệnh npm bạn chạy trong terminal
  • Registry — cơ sở dữ liệu packages tại registry.npmjs.org
  • Website — npmjs.com để tìm kiếm và xem docs của packages

npm vs yarn vs pnpm

Thuộc tính npm yarn pnpm
Tạo bởi npm Inc. (GitHub) Meta (Facebook) Zoltan Kochan
Cài đặt Đi kèm NodeJS npm i -g yarn npm i -g pnpm
Tốc độ Trung bình Nhanh (parallel) Rất nhanh (content-addressable)
Disk space Nhiều (copy files) Nhiều (copy files) Ít nhất (symlinks + store)

Workspaces Có (npm v7+) Có Có (tốt nhất)
Nên dùng khi Mặc định, đơn giản Monorepo lớn Disk quan trọng, CI nhanh
💡 Nên dùng cái nào?

Nếu bạn mới bắt đầu, dùng npm vì nó đã có sẵn, không cần cài thêm. Khi làm monorepo hoặc team lớn, pnpm tiết kiệm disk và CI nhanh hơn đáng kể. Đừng mix — trong một project chỉ dùng một package manager.

Tại sao phân biệt dependencies và devDependencies?

Khi deploy lên production, bạn thường chạy npm install --omit=dev — lệnh này bỏ qua devDependencies. Điều này giúp:

  • Giảm kích thước thư mục node_modules đáng kể (đôi khi 50-70%)
  • Deploy nhanh hơn, Docker image nhỏ hơn
  • Giảm attack surface bảo mật (ít packages = ít vulnerability)
ShellQuy tắc phân loại
# ─── dependencies: cần cho production ────────────────────────────
npm install express mongoose jsonwebtoken bcrypt dotenv
# Đây là những package mà server ĐANG CHẠY cần dùng

# ─── devDependencies: chỉ cần khi development/build ──────────────
npm install --save-dev nodemon jest eslint prettier typescript
# Những package này chỉ cần khi bạn đang VIẾT CODE

# ─── Cài production chỉ (khi deploy) ─────────────────────────────
npm install --omit=dev
# Hoặc (cách cũ): npm install --production

7.3 Semantic Versioning — Đọc Số Version

npm dùng chuẩn Semantic Versioning (semver) cho tất cả packages. Hiểu semver giúp bạn biết khi nào update an toàn và khi nào có thể gây breaking change.

Bảng tổng hợp Range Operators

Operator Ví dụ Chấp nhận Không chấp nhận
^ (caret) ^2.4.1 2.4.1, 2.5.0, 2.9.9 3.0.0, 1.9.9
~ (tilde) ~2.4.1 2.4.1, 2.4.8, 2.4.99 2.5.0, 3.0.0
Chính xác 2.4.1 2.4.1 (chỉ version này) 2.4.2, 2.5.0
* (wildcard) * Mọi version (kể cả major) (không có giới hạn)
>= >=2.4.0 2.4.0, 3.0.0, 99.0.0 2.3.9
Range 2.0.0 - 3.0.0 2.0.0 đến 3.0.0 1.x, 3.0.1+
⚠️ Tại sao không dùng * (wildcard) cho mọi thứ?

Dùng * nghĩa là "chấp nhận bất kỳ version nào kể cả major". Nếu package X ra version 3.0.0 với breaking changes, app của bạn sẽ tự động "nâng cấp" và có thể bị lỗi ngay lập tức. Đây là lý do package-lock.json tồn tại — để lock chính xác version đã test.

Kiểm tra và cập nhật packages

ShellQuản lý versions
# Xem packages nào có update
npm outdated
# Package  Current  Wanted  Latest
# express  4.17.1   4.19.2  4.19.2    ← Wanted = trong range ^4.17.1
# mongoose 7.0.0    7.6.1   8.3.1     ← Latest 8.x nhưng Wanted vẫn 7.x (major!)

# Cập nhật packages trong range đã khai báo (an toàn)
npm update

# Cập nhật một package cụ thể lên latest (CÓ THỂ BREAKING!)
npm install express@latest

# Kiểm tra semver: version nào khớp range?
node -e "console.log(require('semver').satisfies('2.5.0', '^2.4.1'))"
# true

7.4 package-lock.json và node_modules

package-lock.json là file quan trọng mà nhiều người bỏ qua hoặc thậm chí thêm vào .gitignore (sai!). Hãy hiểu tại sao nó quan trọng:

Vấn đề không có lock file

⚠️ "Works on my machine" vì không có lock file

Developer A cài dependencies hôm nay → package X 2.4.1 được cài.
Developer B pull code tuần sau → npm install → package X 2.5.0 được cài (có bug mới).
CI server → X 2.5.1 được cài.
Production → X 2.5.2 được cài.
Tất cả đang chạy các version KHÁC NHAU, dù cùng một source code!

package-lock.json giải quyết vấn đề này

JSONpackage-lock.json (fragment)
{
  "name": "my-app",
  "version": "1.0.0",
  "lockfileVersion": 3,
  "requires": true,
  "packages": {
    "": {
      "name": "my-app",
      "version": "1.0.0",
      "dependencies": { "express": "^4.19.2" }
    },
    "node_modules/express": {
      "version": "4.19.2",          // ← EXACT version, không phải ^4.19.2
      "resolved": "https://registry.npmjs.org/express/-/express-4.19.2.tgz",
      "integrity": "sha512-...",    // ← SHA hash để verify file không bị tamper
      "dependencies": {
        "accepts": "~1.3.8",        // ← Dependencies của express cũng bị lock!
        "body-parser": "1.20.2",
        "debug": "2.6.9",
        ...
      }
    },
    "node_modules/accepts": {
      "version": "1.3.8",           // ← Transitive dep cũng lock
      ...
    }
  }
}

package-lock.json lock cả transitive dependencies (dependencies của dependencies). Nhờ vậy, mọi người trong team, CI và production đều cài y hệt nhau.

7.5 npm Scripts — Automation

Thay vì ghi nhớ các lệnh dài, đặt chúng vào scripts trong package.json. npm scripts chạy trong một shell environment đặc biệt nơi node_modules/.bin được thêm vào PATH — nên bạn có thể dùng tên binary trực tiếp.

Scripts cơ bản

JSONpackage.json — scripts section
{
  "scripts": {
    // ── Built-in scripts (không cần "run") ──────────────────────────
    "start": "node src/index.js",      // npm start
    "test": "jest",                    // npm test
    "stop": "...",                     // npm stop
    "restart": "...",                  // npm restart

    // ── Custom scripts (cần "npm run ") ──────────────────────
    "dev": "nodemon src/index.js",     // npm run dev
    "dev:debug": "node --inspect src/index.js", // npm run dev:debug

    // ── Build ────────────────────────────────────────────────────────
    "build": "tsc --project tsconfig.json",
    "build:watch": "tsc --watch",

    // ── Lint & format ────────────────────────────────────────────────
    "lint": "eslint src/ --ext .js,.ts",
    "lint:fix": "eslint src/ --fix",
    "format": "prettier --write \"src/**/*.{js,ts,json}\"",

    // ── Database ─────────────────────────────────────────────────────
    "db:seed": "node scripts/seed.js",
    "db:migrate": "node scripts/migrate.js",

    // ── Kết hợp nhiều lệnh (cross-platform dùng npm-run-all) ────────
    "check": "npm run lint && npm run test",
    "clean": "rimraf dist/ node_modules/.cache/"

}

7.6 Tạo và Publish npm Package

npm không chỉ là nơi tải packages — bạn cũng có thể đóng góp cho cộng đồng bằng cách publish package của riêng mình. Hãy tạo một package thực tế: format-vnd — format số thành tiền VND. 

ShellTạo cấu trúc package
# Tạo thư mục package
mkdir format-vnd
cd format-vnd
npm init  # Điền đầy đủ thông tin

# Cài dependencies (nếu cần)
# Package này không cần dependencies nào!

# Cấu trúc thư mục:
# format-vnd/
# ├── src/
# │   └── index.js      ← Source chính
# ├── test/
# │   └── index.test.js ← Tests
# ├── package.json
# ├── .npmignore        ← Files không publish
# └── README.md
JavaScriptsrc/index.js
'use strict';

/**
 * Format số thành chuỗi tiền VND
 * @param {number} amount - Số tiền
 * @param {object} [options]
 * @param {boolean} [options.symbol=true] - Thêm ký hiệu ₫ hoặc VND
 * @param {string} [options.style='symbol'] - 'symbol' (₫) hoặc 'code' (VND)
 * @returns {string}
 *
 * @example
 * formatVND(1500000)              // '1.500.000 ₫'
 * formatVND(1500000, { style: 'code' }) // '1.500.000 VND'
 * formatVND(1500000, { symbol: false }) // '1.500.000'
 */
function formatVND(amount, options = {}) {
  const { symbol = true, style = 'symbol' } = options;

  if (typeof amount !== 'number' || isNaN(amount)) {
    throw new TypeError(`formatVND: expected a number, got ${typeof amount}`);
  }

  // Dùng Intl.NumberFormat cho format chuẩn
  const formatter = new Intl.NumberFormat('vi-VN', {
    style: 'decimal',
    minimumFractionDigits: 0,
    maximumFractionDigits: 0,
  });

  const formatted = formatter.format(Math.abs(amount));
  const prefix = amount < 0 ? '-' : '';

  if (!symbol) return `${prefix}${formatted}`;
  if (style === 'code') return `${prefix}${formatted} VND`;
  return `${prefix}${formatted} ₫`;
}

/**
 * Parse chuỗi tiền VND về number
 * @param {string} str - Ví dụ: '1.500.000 ₫' hoặc '1500000'
 * @returns {number}
 */
function parseVND(str) {
  if (typeof str !== 'string') {
    throw new TypeError(`parseVND: expected a string, got ${typeof str}`);
  }
  // Xóa ký hiệu tiền, dấu chấm ngăn cách
  const cleaned = str
    .replace(/[₫VND\s]/g, '')
    .replace(/\./g, '');
  const num = parseInt(cleaned, 10);
  if (isNaN(num)) throw new Error(`parseVND: không thể parse "${str}"`);
  return num;
}

/**
 * So sánh hai giá trị tiền (trả về âm/0/dương như Array.sort comparator)
 */
function compareVND(a, b) {
  return a - b;
}

module.exports = { formatVND, parseVND, compareVND };
JavaScripttest/index.test.js
const { formatVND, parseVND } = require('../src/index');

describe('formatVND', () => {
  test('format số dương cơ bản', () => {
    expect(formatVND(1500000)).toBe('1.500.000 ₫');
    expect(formatVND(0)).toBe('0 ₫');
    expect(formatVND(999)).toBe('999 ₫');
  });

  test('format số âm', () => {
    expect(formatVND(-50000)).toBe('-50.000 ₫');
  });

  test('options: symbol=false', () => {
    expect(formatVND(1500000, { symbol: false })).toBe('1.500.000');
  });

  test('options: style=code', () => {
    expect(formatVND(1500000, { style: 'code' })).toBe('1.500.000 VND');
  });

  test('throw khi không phải number', () => {
    expect(() => formatVND('1000')).toThrow(TypeError);
    expect(() => formatVND(NaN)).toThrow(TypeError);
  });
});

describe('parseVND', () => {

npm workspaces — Monorepo đơn giản

Từ npm v7, có thể quản lý nhiều packages trong một repo mà không cần công cụ riêng. Đây là cách setup monorepo đơn giản nhất: 

TextCấu trúc monorepo
my-monorepo/
├── package.json          ← Root package.json (khai báo workspaces)
├── package-lock.json     ← Một lock file duy nhất cho toàn repo
├── node_modules/         ← Shared node_modules (deduped)
└── packages/
    ├── shared-utils/     ← Package dùng chung
    │   ├── package.json  (name: "@myrepo/shared-utils")
    │   └── src/index.js
    └── api/              ← API server
        ├── package.json  (name: "@myrepo/api")
        └── src/index.js
JSONpackage.json (root)
{
  "name": "my-monorepo",
  "private": true,
  "workspaces": [
    "packages/*"     // Tất cả thư mục trong packages/ đều là workspace
  ],
  "scripts": {
    // Chạy script trong TẤT CẢ workspaces
    "build": "npm run build --workspaces",
    "test":  "npm test --workspaces --if-present",

    // Chạy trong workspace CỤ THỂ
    "dev:api": "npm run dev --workspace=packages/api"
  }
}
JSONpackages/api/package.json
{
  "name": "@myrepo/api",
  "version": "0.1.0",
  "dependencies": {
    // Tham chiếu workspace khác — npm tự resolve local
    "@myrepo/shared-utils": "*",
    "express": "^4.19.2"
  },
  "scripts": {
    "dev": "nodemon src/index.js",
    "start": "node src/index.js"
  }
}
ShellDùng workspaces
# Cài tất cả dependencies cho toàn monorepo (root directory)
npm install

# Cài package cho workspace cụ thể
npm install axios --workspace=packages/api

# Chạy script trong workspace cụ thể
npm run dev --workspace=packages/api

# npm tự động symlink @myrepo/shared-utils → packages/shared-utils
# nên require('@myrepo/shared-utils') sẽ dùng code local!
📚 Tóm tắt chương 7
  • npm gồm 3 thứ: CLI tool, registry (npmjs.com), website — yarn và pnpm là alternatives
  • package.json chứa metadata, dependencies và scripts; private: true ngăn publish nhầm
  • dependencies cần cho production; devDependencies chỉ cho development/build; peerDependencies host phải tự cài
  • Semver: ^ cho phép minor+patch, ~ chỉ cho phép patch, exact version lock chặt nhất
  • package-lock.json lock exact version của mọi transitive dep — luôn commit file này
  • Dùng npm ci trong CI/CD; dùng npm install khi development
  • npm scripts hỗ trợ pre/post hooks, chạy binaries từ node_modules/.bin tự động
  • npm audit kiểm tra vulnerability — chạy định kỳ và trong CI
  • npm workspaces quản lý monorepo mà không cần công cụ riêng
