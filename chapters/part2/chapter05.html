Chương 5: Async Programming — Callback, Promise, async/await

Lập trình bất đồng bộ là linh hồn của NodeJS. Chương này giải thích tại sao cần async, các pattern từ cổ điển (callback) đến hiện đại (async/await), cách xử lý lỗi đúng cách, và cách Event Loop thực sự hoạt động bên trong.

🎯 Sau chương này bạn sẽ
  • Hiểu tại sao lập trình bất đồng bộ là cốt lõi của NodeJS
  • Viết và đọc hiểu code dùng callback, Promise, và async/await
  • Xử lý lỗi đúng cách trong cả ba pattern
  • Chạy nhiều Promise song song với Promise.all, Promise.allSettled
  • Tránh những lỗi phổ biến: callback hell, unhandled rejection, await trong vòng lặp
  • Hiểu Event Loop: call stack, microtask queue, task queue và thứ tự thực thi

5.1 Vấn đề: Tại sao cần Async?

JavaScript là single-threaded — chỉ có một luồng xử lý, làm một việc tại một thời điểm. Nếu một thao tác mất 200ms (đọc file, gọi API, truy vấn database), toàn bộ chương trình phải đứng chờ — không xử lý được gì khác.

Phép so sánh: Nhà hàng vs Cửa hàng tạp hóa

Hãy tưởng tượng bạn là nhân viên phục vụ tại một nhà hàng có 10 bàn:

  • Blocking (cửa hàng tạp hóa): Bạn nhận order của bàn 1, đứng ở bếp chờ 20 phút cho đến khi món ăn xong, mang ra rồi mới quay lại nhận order của bàn 2. Khách ở bàn 2–10 phải chờ cả tiếng!
  • Non-blocking (nhà hàng thực sự): Bạn nhận order của tất cả 10 bàn, giao mỗi order cho bếp (OS/libuv). Trong khi bếp nấu, bạn tiếp tục phục vụ khách khác. Khi bếp gọi "Bàn 3 xong!", bạn mang ra ngay. Tất cả được phục vụ hiệu quả.

Trong khi chờ database trả lời (thường 10–100ms), CPU của bạn hoàn toàn rảnh rỗi. Non-blocking I/O tận dụng thời gian chờ đó để xử lý các request khác. Đây là lý do NodeJS có thể xử lý hàng nghìn request đồng thời chỉ với một thread.

5.2 Callback Pattern

Callback là cách đầu tiên JavaScript xử lý async. Ý tưởng: "Khi xong việc này, gọi cho tôi biết bằng cách gọi hàm callback này."

Error-first Callback Convention

Quy ước trong NodeJS: tham số đầu tiên của callback luôn là error (nếu không có lỗi thì là null). Tham số thứ hai trở đi là kết quả. 

        

          JavaScript
          callbacks.js
          
        

        const fs = require('fs');

// Error-first callback: (error, result) => {}
fs.readFile('./config.json', 'utf8', (err, data) => {
  // Luôn kiểm tra lỗi TRƯỚC
  if (err) {
    console.error('Không đọc được file:', err.message);
    return; // QUAN TRỌNG: return để không chạy tiếp
  }

  // Chỉ dùng data khi không có lỗi
  const config = JSON.parse(data);
  console.log('Port:', config.port);
});

// Tự viết hàm dùng error-first callback
function fetchUserFromDB(userId, callback) {
  // Giả lập query database (thực tế là async)
  setTimeout(() => {
    if (userId <= 0) {
      callback(new Error('userId phải là số dương'));
      return;
    }
    // Thành công
    callback(null, {
      id: userId,
      name: 'Nguyễn Văn A',
      email: 'a@example.com'
    });
  }, 100);  // giả lập 100ms query time
}

// Sử dụng
fetchUserFromDB(1, (err, user) => {
  if (err) {
    console.error('Lỗi:', err.message);
    return;
  }
  console.log('User:', user);
});

Callback Hell — Cái bẫy của người mới

Vấn đề xảy ra khi bạn cần làm nhiều thao tác async nối tiếp nhau. Code lồng nhau ngày càng sâu, trông như một cái kim tự tháp: 

        

          JavaScript
          callback-hell.js
          
        

        // ❌ Callback Hell — Pyramid of Doom
// Kịch bản: đọc config → kết nối DB → lấy user → lấy orders → tính tổng

fs.readFile('./config.json', 'utf8', (err, configData) => {
  if (err) { handleError(err); return; }

  const config = JSON.parse(configData);

  connectDatabase(config.dbUrl, (err, db) => {
    if (err) { handleError(err); return; }

    db.findUser(userId, (err, user) => {
      if (err) { handleError(err); return; }

      db.findOrders(user.id, (err, orders) => {
        if (err) { handleError(err); return; }

        calculateTotal(orders, (err, total) => {
          if (err) { handleError(err); return; }

          // Cuối cùng mới đến kết quả
          // Nhưng đến đây code đã thụt vào quá sâu!
          console.log(`User ${user.name} có tổng đơn hàng: ${total}`);
        });
      });
    });
  });
});

Vấn đề của callback hell không chỉ là code xấu. Khó xử lý lỗi đúng chỗ, khó tái sử dụng logic, không thể dùng try/catch, và rất khó test. Promise ra đời để giải quyết.

5.3 Promise — Giải pháp cho Callback Hell

Promise là object đại diện cho một giá trị có thể có trong tương lai (hoặc thất bại). Thay vì truyền callback vào, bạn nhận về một Promise object và xử lý sau.

3 trạng thái của Promise

        

          JavaScript
          promises.js
          
        

        // === TẠO PROMISE TỪ ĐẦU ===
function fetchUserFromDB(userId) {
  return new Promise((resolve, reject) => {
    // Thực hiện công việc async
    setTimeout(() => {
      if (userId <= 0) {
        reject(new Error('userId phải là số dương'));
        return;
      }
      resolve({
        id: userId,
        name: 'Nguyễn Văn A',
        email: 'a@example.com'
      });
    }, 100);
  });
}

// === DÙNG .then() .catch() .finally() ===
fetchUserFromDB(1)
  .then(user => {
    console.log('User:', user.name);
    return user.id; // Giá trị trả về từ .then() → .then() tiếp theo nhận được
  })
  .then(userId => {
    console.log('User ID:', userId);
  })
  .catch(err => {
    // Bắt lỗi từ BẤT KỲ .then() nào phía trên
    console.error('Lỗi:', err.message);
  })
  .finally(() => {
    // Luôn chạy, dù thành công hay thất bại
    console.log('Done!');
  });

// === PROMISE CHAINING ===
// Rewrite callback hell thành promise chain — phẳng và dễ đọc hơn nhiều
function processUserOrder(userId) {
  return readConfig('./config.json')
    .then(config => connectDatabase(config.dbUrl))
    .then(db => db.findUser(userId))
    .then(user => db.findOrders(user.id)) // db không accessible! xem phiên bản fix dưới
    .then(orders => calculateTotal(orders))
    .then(total => {
      console.log(`Tổng đơn hàng: ${total}`);
      return total;
    })
    .catch(err => {
      console.error('Lỗi trong pipeline:', err.message);
      throw err; // re-throw để caller biết có lỗi
    });
}

// Fix: dùng closure để giữ reference
function processUserOrderFixed(userId) {
  let _db; // giữ db reference

  return readConfig('./config.json')
    .then(config => connectDatabase(config.dbUrl))
    .then(db => {
      _db = db;
      return _db.findUser(userId);
    })
    .then(user => _db.findOrders(user.id))
    .then(orders => calculateTotal(orders))
    .catch(err => {
      console.error('Lỗi:', err.message);
      throw err;
    });
}

// === PROMISIFY CALLBACK FUNCTIONS ===
const util = require('util');
const fs = require('fs');

// Chuyển callback-style thành Promise
const readFile = util.promisify(fs.readFile);
const writeFile = util.promisify(fs.writeFile);

// Giờ dùng được .then()
readFile('./data.json', 'utf8')
  .then(data => JSON.parse(data))
  .then(obj => console.log('Data:', obj))
  .catch(err => console.error('Lỗi:', err));

5.4 Promise Combinators

Khi cần xử lý nhiều Promise cùng lúc, JavaScript cung cấp các hàm "combinator". Mỗi hàm có hành vi khác nhau khi gặp Promise bị reject. 

        

          JavaScript
          promise-combinators.js
          
        

        // Giả lập fetch API
function fetchUser(id) {
  return new Promise(resolve =>
    setTimeout(() => resolve({ id, name: `User ${id}` }), Math.random() * 200)
  );
}

function fetchPosts(userId) {
  return new Promise(resolve =>
    setTimeout(() => resolve([`Post của user ${userId}`]), Math.random() * 300)
  );
}

// === Promise.all — chờ tất cả, fail nhanh nếu 1 cái fail ===
async function loadDashboard(userId) {
  console.time('dashboard');

  // Song song: fetch user VÀ posts cùng lúc (không await lần lượt!)
  const [user, posts, settings] = await Promise.all([
    fetchUser(userId),
    fetchPosts(userId),
    fetchSettings(userId)
  ]);

  console.timeEnd('dashboard'); // Nhanh hơn await lần lượt rất nhiều

  return { user, posts, settings };
}

// === Promise.allSettled — chờ tất cả, không quan tâm có fail không ===
async function fetchMultipleSources(urls) {
  const results = await Promise.allSettled(
    urls.map(url => fetch(url).then(r => r.json()))
  );

  const successful = [];
  const failed = [];

  for (const result of results) {
    if (result.status === 'fulfilled') {
      successful.push(result.value);
    } else {
      failed.push(result.reason.message);
    }
  }

  console.log(`Thành công: ${successful.length}, Thất bại: ${failed.length}`);
  return successful;
}

// === Promise.race — timeout pattern ===
function withTimeout(promise, ms) {
  const timeout = new Promise((_, reject) =>
    setTimeout(() => reject(new Error(`Timeout sau ${ms}ms`)), ms)
  );
  return Promise.race([promise, timeout]);
}

// Fetch với timeout 5 giây
withTimeout(fetchUser(1), 5000)
  .then(user => console.log('User:', user))
  .catch(err => console.error('Lỗi:', err.message));

// === Promise.any — dùng server nhanh nhất trong nhiều mirrors ===
async function fetchFromFastestMirror(path) {
  const mirrors = [
    `https://mirror1.example.com${path}`,
    `https://mirror2.example.com${path}`,
    `https://mirror3.example.com${path}`
  ];

  try {
    const data = await Promise.any(
      mirrors.map(url => fetch(url).then(r => {
        if (!r.ok) throw new Error(`HTTP ${r.status}`);
        return r.json();
      }))
    );
    return data;
  } catch (err) {
    // AggregateError: tất cả đều fail
    throw new Error('Tất cả mirrors đều không trả lời');
  }
}

5.5 async/await — Syntax đẹp nhất

async/await là "syntactic sugar" trên Promise — bên dưới vẫn là Promise, nhưng code trông như synchronous, dễ đọc và viết hơn nhiều. 

        

          JavaScript
          async-await.js
          
        

        const fs = require('fs/promises');

// async function luôn trả về Promise
async function readAndParseJSON(filePath) {
  // await tạm dừng function, chờ Promise resolve
  const content = await fs.readFile(filePath, 'utf8');
  const data = JSON.parse(content);
  return data; // Được wrap trong Promise.resolve(data) tự động
}

// Sử dụng: vẫn là Promise từ bên ngoài
readAndParseJSON('./config.json')
  .then(config => console.log(config))
  .catch(err => console.error(err));

// Hoặc await trong async context khác
async function main() {
  const config = await readAndParseJSON('./config.json');
  console.log('Port:', config.port);
}

// === SO SÁNH Promise chain vs async/await ===

// Promise chain
function getUserDataPromise(userId) {
  return connectDB()
    .then(db => db.findUser(userId))
    .then(user => {
      return db.findOrders(user.id) // db không accessible!
        .then(orders => ({ user, orders }));
    })
    .then(({ user, orders }) => ({
      ...user,
      orderCount: orders.length
    }));
}

// async/await — sạch hơn nhiều, dễ đọc như sync code
async function getUserData(userId) {
  const db = await connectDB();
  const user = await db.findUser(userId);
  const orders = await db.findOrders(user.id);  // db accessible!

  return {
    ...user,
    orderCount: orders.length
  };
}

// === SEQUENTIAL vs PARALLEL ===

// ❌ SAI: await trong vòng lặp = sequential (chậm)
async function fetchUsersSequential(ids) {
  const users = [];
  for (const id of ids) {
    const user = await fetchUser(id); // Chờ từng cái một!
    users.push(user);
  }
  return users;
  // Nếu mỗi fetch mất 100ms và có 10 id → tổng 1000ms
}

// ✅ ĐÚNG: song song bằng Promise.all
async function fetchUsersParallel(ids) {
  const users = await Promise.all(ids.map(id => fetchUser(id)));
  return users;
  // Tất cả fetch chạy song song → chỉ tốn ~100ms
}

// ✅ ĐÚNG khi cần sequential nhưng muốn code đẹp
async function processSequentially(items) {
  const results = [];
  for (const item of items) {
    // reduce cũng dùng được nhưng phức tạp hơn
    const result = await processItem(item);
    results.push(result);
  }
  return results;
}

5.6 Error Handling Đúng Cách

Async code có nhiều pitfall về error handling. Bỏ sót một catch có thể làm server crash hoặc tệ hơn — chạy tiếp với dữ liệu sai. 

        

          JavaScript
          error-handling.js
          
        

        // === try/catch với async/await ===
async function processOrder(orderId) {
  try {
    const order = await db.findOrder(orderId);

    if (!order) {
      throw new Error(`Order ${orderId} không tồn tại`);
    }

    const payment = await paymentService.charge(order.total);
    await db.updateOrder(orderId, { status: 'paid', paymentId: payment.id });

    return { success: true, order };

  } catch (err) {
    // Xử lý từng loại lỗi khác nhau
    if (err.code === 'ORDER_NOT_FOUND') {
      return { success: false, error: 'Order không tồn tại' };
    }
    if (err.code === 'PAYMENT_DECLINED') {
      await db.updateOrder(orderId, { status: 'payment_failed' });
      return { success: false, error: 'Thanh toán bị từ chối' };
    }
    // Lỗi không biết: log và re-throw
    console.error(`Lỗi không xử lý được trong processOrder(${orderId}):`, err);
    throw err;

  } finally {
    // Luôn chạy: cleanup resources
    await db.releaseConnection();
  }
}

// === Custom Error Classes ===
class AppError extends Error {
  constructor(message, code, statusCode = 500) {
    super(message);
    this.name = 'AppError';
    this.code = code;
    this.statusCode = statusCode;
    Error.captureStackTrace(this, this.constructor);
  }
}

class NotFoundError extends AppError {
  constructor(resource, id) {
    super(`${resource} với id '${id}' không tồn tại`, 'NOT_FOUND', 404);
    this.name = 'NotFoundError';
  }
}

class ValidationError extends AppError {
  constructor(field, message) {
    super(`Validation thất bại: ${field} — ${message}`, 'VALIDATION_ERROR', 400);
    this.name = 'ValidationError';
    this.field = field;
  }
}

// Sử dụng
async function getUser(id) {
  if (!id || typeof id !== 'number') {
    throw new ValidationError('id', 'phải là số nguyên dương');
  }

  const user = await db.findById(id);
  if (!user) {
    throw new NotFoundError('User', id);
  }

  return user;
}

// === UNHANDLED PROMISE REJECTION ===
// Cực kỳ nguy hiểm — không có catch thì NodeJS bỏ qua lỗi

// ❌ BAD: không có catch
fetchData().then(data => processData(data));
// Nếu processData() throw → lỗi bị nuốt mất

// ✅ GOOD: luôn có catch
fetchData()
  .then(data => processData(data))
  .catch(err => console.error('Lỗi:', err));

// Bắt unhandled rejection toàn app (safety net)
process.on('unhandledRejection', (reason, promise) => {
  console.error('Unhandled Promise Rejection:', reason);
  // Trong production: log và graceful shutdown
  process.exit(1);
});

// === RETRY VỚI EXPONENTIAL BACKOFF ===
async function retryWithBackoff(fn, maxRetries = 3, baseDelayMs = 1000) {
  let lastError;

  for (let attempt = 1; attempt <= maxRetries; attempt++) {
    try {
      return await fn();
    } catch (err) {
      lastError = err;

      // Không retry nếu là lỗi client (4xx)
      if (err.statusCode >= 400 && err.statusCode < 500) {
        throw err;
      }

      if (attempt === maxRetries) break;

      // Exponential backoff: 1s, 2s, 4s, 8s...
      const delay = baseDelayMs * Math.pow(2, attempt - 1);
      const jitter = Math.random() * 500; // Random jitter để tránh thundering herd
      console.log(`Attempt ${attempt} thất bại, thử lại sau ${delay + jitter}ms...`);
      await new Promise(resolve => setTimeout(resolve, delay + jitter));
    }
  }

  throw new Error(`Thất bại sau ${maxRetries} lần: ${lastError.message}`);
}

// Sử dụng
const data = await retryWithBackoff(
  () => fetch('https://api.example.com/data').then(r => r.json()),
  3,    // max 3 lần
  1000  // bắt đầu với 1 giây
);

5.7 Event Loop — Hiểu Sâu Bên Trong

Event Loop là trái tim của NodeJS. Nó quyết định code nào chạy khi nào. Hiểu Event Loop giúp bạn debug được những bug khó hiểu nhất và viết code hiệu quả hơn.

Các thành phần của Event Loop

Thứ tự thực thi: process.nextTick vs Promise.then vs setTimeout

        

          JavaScript
          event-loop-demo.js
          
        

        console.log('1. Synchronous — chạy ngay');

setTimeout(() => {
  console.log('5. setTimeout(0) — Macrotask (chạy sau cùng)');
}, 0);

Promise.resolve()
  .then(() => {
    console.log('3. Promise.then — Microtask');
  })
  .then(() => {
    console.log('4. Promise.then lần 2 — vẫn Microtask');
  });

process.nextTick(() => {
  console.log('2. process.nextTick — Microtask ưu tiên cao nhất');
});

console.log('1b. Synchronous — vẫn đang chạy sync');

// Output:
// 1. Synchronous — chạy ngay
// 1b. Synchronous — vẫn đang chạy sync
// 2. process.nextTick — Microtask ưu tiên cao nhất
// 3. Promise.then — Microtask
// 4. Promise.then lần 2 — vẫn Microtask
// 5. setTimeout(0) — Macrotask (chạy sau cùng)

// === VÍ DỤ PHỨC TẠP HƠN ===
console.log('--- Ví dụ 2 ---');

setTimeout(() => console.log('timeout 1'), 0);
setTimeout(() => console.log('timeout 2'), 0);

Promise.resolve()
  .then(() => {
    console.log('promise 1');
    process.nextTick(() => console.log('nextTick trong promise'));
  })

  console.log('nextTick 1');
  process.nextTick(() => console.log('nextTick lồng nhau'));

// Output:
// nextTick 1
// nextTick lồng nhau     ← nextTick được gọi trong nextTick cũng ưu tiên cao
// promise 1
// nextTick trong promise ← nextTick trong promise.then cũng được ưu tiên
// promise 2
// timeout 1
// timeout 2

// === setImmediate vs setTimeout(fn, 0) ===
// Trong I/O callback: setImmediate chạy trước setTimeout
// Ngoài I/O: thứ tự không đảm bảo

const fs = require('fs');
fs.readFile('./file.txt', () => {
  setTimeout(() => console.log('timeout'), 0);
  setImmediate(() => console.log('immediate'));
  // Output đảm bảo:
  // immediate
  // timeout
});
⚠️ Đừng block Event Loop

Mọi code synchronous dài sẽ block Event Loop. Ví dụ: tính toán nặng, vòng lặp triệu lần, parse JSON file 100MB. Trong thời gian đó NodeJS không thể xử lý request nào khác. Giải pháp: dùng worker_threads cho CPU-intensive tasks, hoặc chia nhỏ công việc bằng setImmediate.

Thực hành tốt: Không block Event Loop

        

          JavaScript
          non-blocking-heavy.js
          
        

        // ❌ Block Event Loop — tính fibonacci ngay trên main thread
function fibSlow(n) {
  if (n <= 1) return n;
  return fibSlow(n - 1) + fibSlow(n - 2);
}
// fibSlow(45) → block 5+ giây!

// ✅ Dùng Worker Threads cho CPU-intensive tasks
const { Worker, isMainThread, parentPort, workerData } = require('worker_threads');

if (isMainThread) {
  // Code chạy trên main thread
  function fibInWorker(n) {
    return new Promise((resolve, reject) => {
      const worker = new Worker(__filename, { workerData: n });
      worker.on('message', resolve);
      worker.on('error', reject);
    });
  }

  // Main thread không bị block
  fibInWorker(45).then(result => {
    console.log('Kết quả fib(45):', result);
  });

  // Server vẫn chạy bình thường trong khi worker tính toán
  console.log('Server vẫn xử lý requests bình thường...');

} else {
  // Code chạy trong worker thread
  function fib(n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);
  }
  parentPort.postMessage(fib(workerData));
}

// ✅ Chia nhỏ công việc bằng setImmediate (cho array lớn)
async function processLargeArray(items, processFn) {
  const BATCH_SIZE = 100;
  const results = [];

  for (let i = 0; i < items.length; i += BATCH_SIZE) {
    const batch = items.slice(i, i + BATCH_SIZE);
    const batchResults = batch.map(processFn);
    results.push(...batchResults);

    // Nhường Event Loop sau mỗi batch
    await new Promise(resolve => setImmediate(resolve));
  }

  return results;
}
📚 Tóm tắt chương 5
  • Tại sao Async: NodeJS single-threaded nên I/O blocking sẽ làm nghẽn toàn bộ server. Non-blocking I/O cho phép xử lý nhiều request đồng thời chỉ với 1 thread.
  • Callback: Pattern cổ điển, dùng error-first convention (err, result) => {}. Tránh callback hell bằng cách extract functions ra ngoài hoặc dùng Promise.
  • Promise: Object đại diện cho giá trị tương lai. 3 trạng thái: pending, fulfilled, rejected. Dùng .then(), .catch(), .finally(). Có thể chain.
  • Promise Combinators: Promise.all — song song, fail fast; Promise.allSettled — song song, không fail; Promise.race — ai xong trước; Promise.any — ai thành công trước.
  • async/await: Syntactic sugar trên Promise. Dùng try/catch thay .catch(). Cẩn thận await trong vòng lặp — dùng Promise.all nếu muốn song song.
  • Error Handling: Luôn có catch. Dùng custom error classes để phân biệt loại lỗi. Bắt unhandledRejection toàn app làm safety net.
  • Event Loop: Microtask (Promise.then, process.nextTick) ưu tiên hơn Macrotask (setTimeout, I/O callbacks). process.nextTick ưu tiên nhất trong microtask. Không bao giờ block Event Loop bằng code CPU-intensive.

Dễ

5.1 Promisify với util.promisify

Chuyển đổi ba hàm callback-style sau sang Promise dùng util.promisify:

  • fs.readFile — đọc file
  • fs.writeFile — ghi file
  • dns.lookup — phân giải DNS của một domain

Viết một script nhận domain từ process.argv[2], phân giải IP bằng dns.lookup promisified, sau đó ghi kết quả vào file dns-results.json. Xử lý đầy đủ error khi domain không tồn tại.

Trung bình

5.2 fetchWithTimeout

Viết hàm fetchWithTimeout(url, timeoutMs, options = {}) thỏa mãn:

  • Fetch URL với node-fetch hoặc built-in fetch (NodeJS 18+)
  • Nếu request mất hơn timeoutMs milliseconds thì reject với lỗi rõ ràng
  • Nếu response status không OK (4xx, 5xx) thì reject với status code
  • Trả về parsed JSON nếu Content-Type là application/json, text nếu không
  • Hỗ trợ abort signal để cancel request khi timeout

Test với các URL thực tế: JSONPlaceholder API, một URL không tồn tại, và mô phỏng timeout.

Khó

5.3 asyncPool — Concurrency Limiter

Viết hàm asyncPool(concurrencyLimit, tasks) trong đó:

  • concurrencyLimit: số task chạy đồng thời tối đa
  • tasks: mảng các hàm () => Promise
  • Hàm chạy tối đa concurrencyLimit tasks cùng lúc
  • Khi một task hoàn thành, task tiếp theo được bắt đầu ngay
  • Trả về mảng kết quả theo thứ tự ban đầu của tasks (không phải theo thứ tự hoàn thành)
  • Nếu có task nào fail, collect tất cả errors và throw AggregateError ở cuối

Test case: Tạo 20 tasks mỗi task delay ngẫu nhiên 100-500ms, chạy với limit = 5. Verify rằng không bao giờ có hơn 5 tasks chạy đồng thời (dùng counter). So sánh thời gian chạy với limit = 1, 5, 10, 20.
